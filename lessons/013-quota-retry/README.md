# บท 013: โควต้าเต็ม ลองใหม่ และ timeout

เมื่อเรียกโมเดลบ่อยหรือใช้บริการฟรีจนเกินโควต้า บริการจะตอบ 429 กลับมา บทนี้เรียนว่าโควต้าหมดหน้าตาเป็นอย่างไร ทำให้โปรแกรมลองใหม่เองอย่างฉลาด (รอแล้วค่อยลอง) และตั้ง timeout ไม่ให้รอนานเกินไป ใช้เวลาประมาณ 45-60 นาที ทำทั้งแบบ Ollama (`.ollama.ts`) และ Google (`.google.ts`)

## จบบทนี้แล้วทำอะไรได้

- อธิบายได้ว่า 429 และ "เครดิตหมด" คืออะไร และดูยอดที่ใช้ไปได้จากที่ไหน
- เขียนฟังก์ชันลองใหม่ที่รอเพิ่มเท่าตัวทุกครั้ง (exponential backoff) และไม่ลองใหม่กับ error ที่ไม่มีวันหาย
- ใช้ `.withRetry()` ของ LangChain ครอบการเรียกโมเดลเพื่อลองใหม่
- ตั้ง timeout ให้การเรียกโมเดลด้วย `.stream(q, { timeout })` และรู้ว่าทำไมไม่ใช้ `invoke`
- รวมยอด token ที่ใช้ไปจากหลายคำถามเพื่อประเมินโควต้า

## เนื้อหา

### 1. 429 และเครดิตหมด

- **Gemini แผนฟรี:** มีลิมิตจำนวนคำขอต่อนาทีและต่อวัน ถ้าเรียกเกินจะได้ 429
- **Ollama Cloud:** ใช้เครดิตหรือโควต้าตามแผนที่สมัคร ถ้าหมดจะเรียกต่อไม่ได้ ข้อความ error จริงตอนเครดิตหมดยังไม่ได้ทดสอบ TODO(6b): ข้อความ error จริงเมื่อเครดิตหมด
- **Ollama ในเครื่อง:** ไม่มีโควต้า จึงไม่เจอ 429 แต่ยังเจอการรอนาน (timeout) ได้ถ้าเครื่องช้า

ดูยอดที่ใช้ไปได้บน dashboard ของแต่ละเจ้า ควรเปิดดูเป็นครั้งคราวระหว่างเรียนจะได้ไม่ตกใจตอนโควต้าหมด TODO(6b): ลิงก์หน้า usage ของ Ollama และ AI Studio

### 2. ลองใหม่เมื่อไรและรอเท่าไร

จากบท 012: ลองใหม่เมื่อเจอ 429 หรือ status 500 ขึ้นไป (เป็นเรื่องชั่วคราว) ไม่ลองใหม่กับ 401 หรือ 404 (ลองกี่ครั้งก็ผิดเหมือนเดิม)

ลองใหม่ทันทีรัวๆ ไม่ช่วย เพราะโควต้ายังไม่คืน จึงต้อง **รอก่อน** และรอนานขึ้นเรื่อยๆ: ครั้งแรกรอ 100 ms ครั้งต่อไป 200 ms, 400 ms ... คือเท่าตัวทุกครั้ง เรียกว่า exponential backoff สูตรของไฟล์ตัวอย่างคือรอ `100 × 2^(i−1)` ms หลังล้มครั้งที่ i

### 3. ขั้นที่ 1: `callWithRetry` กับการเรียกปลอม

```ts
async function callWithRetry<T>(fn: () => Promise<T>, maxRetries: number, log: (line: string) => void): Promise<T>
```

- `fn` คือฟังก์ชันที่จะเรียก (ห่อเป็นฟังก์ชันเพื่อให้เรียกซ้ำได้) `<T>` ทำให้ใช้กับผลชนิดใดก็ได้
- `maxRetries` คือจำนวนครั้งที่ "ลองใหม่" ได้ ไม่นับครั้งแรก
- `log` รับบรรทัดข้อความ ส่ง `console.log` เข้าไปได้เลย
- ใช้ loop `for` ที่เรียก `fn()` ในบล็อก `try` ถ้าสำเร็จคืนผลทันที ถ้าล้มให้ดู status: 429 หรือ 500 ขึ้นไปก็รอแล้วลองใหม่ ส่วนอื่นโยน error ต่อทันที
- ไฟล์ตัวอย่างทดลองกับการเรียกปลอม 2 แบบ (ไม่ยิงเน็ต) คือล้มด้วย 429 สองครั้งแล้วสำเร็จ และล้มด้วย 401 ซึ่งต้องหยุดทันที

### 4. timeout: ไม่ให้รอนานเกินไป

บางครั้งเซิร์ฟเวอร์ไม่ตอบหรือตอบช้ามาก ตั้ง `timeout` (หน่วยมิลลิวินาที) เป็น option ของการเรียกครั้งนั้น ถ้าเกินเวลา การเรียกจะถูกยกเลิกและ throw error ชื่อ `TimeoutError`

```ts
let text = "";
for await (const chunk of await model.stream(q, { timeout: 60_000 })) text += chunk.text;
```

- `model.stream(...)` คืนข้อความทีละชิ้น (chunk) `for await` อ่านทีละชิ้น แล้วเราต่อกันเป็นข้อความเต็ม
- ใส่ `timeout` เป็นอาร์กิวเมนต์ที่ 2 ของ `stream`
- ไฟล์ตัวอย่างตั้งครั้งแรกเป็น `1` ms เพื่อให้ timeout แน่ๆ จะได้เห็น error จริงโดยไม่ต้องรอ

### 5. `.withRetry()`: ให้ LangChain ลองใหม่ให้

ทุกอย่างที่เป็น "Runnable" ของ LangChain (โมเดล, chain, ฟังก์ชันที่ห่อด้วย `RunnableLambda`) มีเมธอด `.withRetry()` ที่คืน Runnable ตัวใหม่ซึ่งลองใหม่ให้เองเมื่อเกิด error

```ts
const askOnce = RunnableLambda.from(async (q: string) => { /* เรียก model.stream แล้วรวมข้อความ */ });
const askWithRetry = askOnce.withRetry({
  stopAfterAttempt: 3,
  onFailedAttempt: (e) => { /* พิมพ์ว่าครั้งนี้ล้มเพราะอะไร */ },
});
const answer = await askWithRetry.invoke("คำถาม");
```

- `RunnableLambda.from(fn)` ห่อฟังก์ชันธรรมดาให้เป็น Runnable
- `stopAfterAttempt: 3` คือลองรวมไม่เกิน 3 ครั้ง (นับครั้งแรกด้วย ต่างจาก `maxRetries` ในหัวข้อ 3)
- `onFailedAttempt` ถูกเรียกทุกครั้งที่ล้ม ใช้พิมพ์ log ได้ แต่ถ้า throw ในนี้การลองใหม่จะหยุดทันที
- ไฟล์ตัวอย่างใช้ตัวนับ `round` ภายนอกนับรอบเอง: ครั้งแรกใช้ `timeout: 1` (ล้มแน่) ครั้งต่อไปใช้ `timeout: 60_000` จึงเห็น "ครั้งที่ 1 ล้ม ครั้งที่ 2 สำเร็จ"

### 6. `maxRetries`: ใช้ได้กับบางโมเดล

- `ChatGoogle` รับ `maxRetries` ตอนสร้างโมเดล (`new ChatGoogle({ ..., maxRetries: 3 })`) และลองใหม่ให้เองเมื่อเจอ 429
- `ChatOllama` **ไม่ใช้** `maxRetries` (ใส่ไปก็ไม่มีผล) จึงต้องใช้ `.withRetry()` แบบหัวข้อ 5

`.withRetry()` ใช้ได้กับทั้งสองโมเดล ไฟล์ในบทนี้จึงใช้วิธีนี้ทั้ง 2 ฝั่งให้โค้ดหน้าตาเหมือนกัน

## จุดที่มักพลาด

- **ใช้ `invoke(q, { timeout })` กับ `ChatOllama`:** การทดลองพบว่า `invoke` + `timeout` **ไม่ throw** แต่คืนข้อความครึ่งเดียวหรือข้อความว่างโดยไม่บอกว่าถูกตัด ผลคือโปรแกรมนึกว่าสำเร็จ จึงต้องตั้ง timeout กับ `.stream()` ซึ่ง throw `TimeoutError` จริง
- **ใส่ `maxRetries` ให้ `ChatOllama` แล้วคิดว่าลองใหม่ให้:** ไม่มีผล ต้องใช้ `.withRetry()`
- **ลองใหม่โดยไม่รอ:** ยิงซ้ำทันทีทำให้โควต้าเต็มเร็วขึ้น ต้องรอและรอนานขึ้นทุกครั้ง
- **ลองใหม่ไม่จำกัดครั้ง:** ต้องกำหนดจำนวนครั้งสูงสุดเสมอ ไม่เช่นนั้นโปรแกรมวนไม่จบเมื่อปัญหาไม่หาย
- **ลองใหม่กับ 401 หรือ 404:** ไม่มีวันหาย (บท 012)
- **throw ใน `onFailedAttempt`:** ทำให้ `.withRetry()` หยุดลองทันที ในฟังก์ชันนั้นพิมพ์ log อย่างเดียวพอ
- **timeout สั้นเกินไปในงานจริง:** `1` ms ใช้เฉพาะตอนทดลอง งานจริงตั้งหลายสิบวินาทีเพราะโมเดลต้องใช้เวลาตอบ

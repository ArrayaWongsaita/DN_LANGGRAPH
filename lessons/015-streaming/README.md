# บท 015: stream ให้คำตอบขึ้นทีละส่วน

ตอนนี้ทุกครั้งที่ถามโมเดล เราต้องรอจนโมเดลเขียนคำตอบจบทั้งหมดแล้วค่อยเห็น ถ้าคำตอบยาวก็ต้องรอนานโดยไม่เห็นอะไรเลย ChatGPT และแชททั่วไปไม่ได้ทำแบบนั้น คำตอบจะค่อยๆ ขึ้นทีละส่วน บทนี้เรียนวิธีทำเช่นนั้นด้วย `.stream()` และ `for await` รวมถึงวิธีสั่งหยุดกลางทางเมื่อเห็นพอแล้ว ใช้เวลาประมาณ 45-60 นาที ทำทั้งแบบ Ollama (`.ollama.ts`) และ Google (`.google.ts`)

## จบบทนี้แล้วทำอะไรได้

- อ่านผลทีละชิ้นจาก `model.stream(...)` ด้วย `for await`
- อธิบายได้ว่าทำไมต้องนับเฉพาะชิ้นที่ `.text` ไม่ว่าง
- เขียนฟังก์ชันที่รับ stream แล้วต่อข้อความ พร้อมวัดเวลาที่ชิ้นแรกมาถึง
- หยุด stream กลางทางด้วย `AbortController` และจับ `AbortError` ได้ถูกต้อง
- เขียนเงื่อนไขหยุดเองจากข้อความที่ได้มาแล้ว

## เชื่อมกับที่รู้แล้ว

| ที่รู้แล้ว | ในบทนี้ |
|---|---|
| TypeScript: `async/await` รอผลลัพธ์ 1 ค่า | `for await` รอผลลัพธ์ทีละค่า หลายครั้ง |
| บท 007: `model.invoke(q)` ได้ `AIMessage` ก้อนเดียว | `model.stream(q)` ได้ `AIMessageChunk` หลายชิ้นต่อกัน |
| บท 013: เคยใช้ `.stream(q, { timeout })` โดยยังไม่ได้อธิบาย | ตอนนี้เข้าใจแล้วว่าวน `for await` ต่อข้อความทีละชิ้น |
| บท 012: error มีชื่อ (`name`) ให้ดู | `AbortError` คือ error ชนิดหนึ่งที่เราสั่งให้เกิดเอง |

## เนื้อหา

บทนี้ต้องผ่านบท 007 ก่อน

### 1. `for await` อ่านค่าที่ทยอยมา

`for...of` วนอาร์เรย์ที่มีข้อมูลครบแล้ว แต่ถ้าข้อมูลทยอยมาทีละชิ้นตามเวลา ต้องใช้ `for await...of` ซึ่งรอชิ้นถัดไปทุกรอบ ขั้นที่ 1 ของไฟล์ตัวอย่างใช้ async generator ปลอม (ฟังก์ชัน `async function*` ที่ใช้ `yield` ส่งค่าออกมาทีละตัว) ส่งคำว่า `ร้าน`, `เปิด`, `ทุก`, `วัน` ห่างกันชิ้นละ 50 ms:

```ts
for await (const piece of fakeStream()) {
  process.stdout.write(piece);
}
```

`process.stdout.write` ต่างจาก `console.log` ตรงที่ไม่ขึ้นบรรทัดใหม่ให้ จึงต่อชิ้นไว้บรรทัดเดียวกันได้ ไฟล์ตัวอย่างคั่นแต่ละชิ้นด้วย `|` เพื่อให้เห็นว่ามาเป็นชิ้นๆ ขั้นที่ 1 ไม่ยิงเน็ต ผลเหมือนกันทุกครั้ง

### 2. `model.stream()` ได้ชิ้นของข้อความ

`await model.stream(คำถาม)` คืนสิ่งที่ใช้กับ `for await` ได้ แต่ละชิ้นเป็น `AIMessageChunk` (ชิ้นส่วนของ `AIMessage`) อ่านข้อความของชิ้นนั้นด้วย `chunk.text` เหมือนที่ใช้กับ `AIMessage`:

```ts
for await (const chunk of await model.stream("แนะนำวิธีเก็บเมล็ดกาแฟให้หอมนาน 3 ข้อ")) {
  process.stdout.write(chunk.text);
}
```

สังเกตว่ามี `await` 2 ที่ ตัวหนึ่งรอให้การเชื่อมต่อเริ่ม (ได้ stream กลับมา) อีกตัวคือ `for await` รอชิ้นถัดไปทุกรอบ

**นับเฉพาะชิ้นที่ `.text` ไม่ว่าง:** ชิ้นสุดท้ายของ stream มักเป็น metadata (เช่น จำนวน token และเหตุที่หยุด) ที่ไม่มีข้อความ ตัวอย่างจึงข้ามชิ้นที่ `chunk.text === ""` และนับเฉพาะชิ้นที่มีข้อความ

**จำนวนชิ้นขึ้นกับ provider:** Ollama จริงส่งมาทีละ token ชิ้นจึงเล็กและมีมาก ส่วนโมเดลที่เราใช้ทดสอบระหว่างสร้างคอร์สผ่านตัวแปลงที่แตกคำตอบเป็นชิ้นปลอมให้ ตัวเลข `ชิ้นที่มีข้อความ` ของแต่ละคนจึงต่างกัน และต่างกันในแต่ละรอบ ที่แน่นอนคือมีอย่างน้อย 2 ชิ้นสำหรับคำตอบยาว

### 3. หยุดกลางทางด้วย `AbortController`

บางครั้งไม่อยากรอให้จบ เช่น ผู้ใช้กดยกเลิก หรือเห็นข้อความพอแล้ว ขั้นตอนคือ

1. สร้าง `const controller = new AbortController()`
2. ส่ง `controller.signal` ให้ `model.stream(คำถาม, { signal: controller.signal })`
3. เมื่ออยากหยุด เรียก `controller.abort()`

หลัง `abort()` การอ่านชิ้นถัดไปจะ throw error ชื่อ `AbortError` (หรือบางกรณี loop จบเองเฉยๆ) เพราะเป็นการหยุดที่เราสั่งเอง จึงต้องจับแล้วถือว่าปกติ แต่ error อื่นต้อง throw ต่อ ไม่เช่นนั้นจะกลืนความผิดพลาดจริงทิ้งไป:

```ts
try {
  for await (const chunk of await model.stream(q, { signal: controller.signal })) {
    // ...
    if (ได้พอแล้ว) controller.abort();
  }
} catch (e) {
  if (!(e instanceof Error && e.name === "AbortError")) throw e;
}
```

ขั้นที่ 2 ตอนท้ายของไฟล์ตัวอย่างถามคำถามที่ต้องตอบยาว (`เล่าประวัติกาแฟแบบละเอียดอย่างน้อย 10 ประโยค`) แล้วสั่ง `abort()` เมื่อได้ชิ้นที่มีข้อความครบ 3 ชิ้น การหยุดกลางทางยังช่วยประหยัด token ด้วย เพราะโมเดลไม่ต้องเขียนส่วนที่เหลือต่อ (ตามที่ provider รองรับ)

## จุดที่มักพลาด

- **ใช้ `for` ธรรมดาแทน `for await`:** ได้ error ว่า stream วนด้วย `for...of` ไม่ได้ ต้องเป็น `for await`
- **ลืม `await` หน้า `model.stream(...)`:** `for await (const c of model.stream(q))` ได้ error ชนิดไม่ตรง ต้องเขียน `for await (const c of await model.stream(q))`
- **นับชิ้นทุกชิ้นรวมชิ้นว่าง:** ชิ้น metadata ท้ายสุดไม่มีข้อความ ทำให้ตัวเลขเกิน 1 ชิ้นเสมอ
- **จับ error ทุกชนิดแล้วเงียบ:** `catch {}` เปล่าๆ ซ่อน error จริง (เช่น เน็ตหลุด) ต้องเช็กว่าเป็น `AbortError` เท่านั้น
- **คิดว่า `abort()` หยุดทันทีทุกตัวอักษร:** ชิ้นที่กำลังเดินทางมาอาจมาถึงก่อน จึงตั้งเงื่อนไขหยุดเป็น "ตั้งแต่ N ขึ้นไป" ไม่ใช่ "เท่ากับ N พอดี"
- **ใช้ `soFar.length` นับตัวอักษรไทย:** `.length` นับหน่วยภายในของ JavaScript ซึ่งอาจไม่ตรงกับที่ตาเห็น ใช้ `[...soFar].length` (เหมือนบท 011)

```
ร้าน|เปิด|ทุก|วัน
ได้ 4 ชิ้น รวมเป็น: ร้านเปิดทุกวัน
```

### ขั้นที่ 2: เทียบกับ checklist

```
--- ขั้นที่ 2: stream จากโมเดลจริง ---
<คำตอบภาษาไทย ขึ้นทีละส่วน>
ชิ้นที่มีข้อความ: N
ความยาวรวม: M ตัวอักษร
--- หยุดกลางทางด้วย AbortController ---
<ข้อความสั้นๆ ที่ได้ก่อนหยุด>
หยุดกลางทาง หลังได้ 3 ชิ้น
```

**`example.ollama` และ `example.google`**
- [ ] ขั้นที่ 1 ตรงทั้ง 2 บรรทัดข้างบน
- [ ] ข้อความที่ stream ออกมาเป็นภาษาไทย
- [ ] `ชิ้นที่มีข้อความ` (N) เป็นเลขตั้งแต่ 2 ขึ้นไป
- [ ] `ความยาวรวม` (M) เป็นเลขมากกว่า 0
- [ ] มีบรรทัด `หยุดกลางทาง หลังได้ 3 ชิ้น`

**`exercise-1.*`**

```
<คำตอบ ขึ้นทีละส่วน>
ได้ทั้งหมด: N ตัวอักษร
ใช้เวลาถึงชิ้นแรก: X ms
```

- [ ] `ได้ทั้งหมด` (N) เป็นเลขมากกว่า 0 และเท่ากับความยาวของข้อความที่พิมพ์ออกมา (ตัดช่องว่างหัวท้าย)
- [ ] มีบรรทัด `ใช้เวลาถึงชิ้นแรก: X ms` โดย X เป็นเลขจำนวนเต็ม

**`exercise-2.*`**

```
ตรวจตัวอย่าง: 49 ตัว=false 50 ตัว=true
<ข้อความที่ได้ก่อนหยุด>
หยุดเมื่อได้ N ตัวอักษร (ตั้งไว้ 50)
```

- [ ] มีบรรทัด `ตรวจตัวอย่าง: 49 ตัว=false 50 ตัว=true` (ไฟล์เรียก `shouldStop` กับข้อมูลตัวอย่าง ไม่เรียกโมเดล)
- [ ] `หยุดเมื่อได้ N ตัวอักษร` โดย N เป็นเลขตั้งแต่ 50 ขึ้นไป (อาจเกิน 50 เล็กน้อยเพราะข้อความมาทีละชิ้น)

ตัวเลข N ของ `exercise-1.*` และ `exercise-2.*` เปลี่ยนทุกครั้งตามคำตอบของโมเดล

> หมายเหตุ: ผลของไฟล์ `.google.ts` ในบทนี้ยังไม่ได้ทดสอบกับ key ของ Google จริง

## แบบฝึกหัด

1. **`exercise-1.*`:** เติม `streamToText(stream, onText)` ให้วนอ่าน stream ทีละชิ้น เรียก `onText` กับข้อความของทุกชิ้นที่มีข้อความ แล้วคืนข้อความทั้งหมดที่ต่อกัน ไฟล์จะพิมพ์คำตอบทีละส่วน จดเวลาที่ข้อความชิ้นแรกมาถึง และพิมพ์ความยาวรวม
2. **`exercise-2.*`:** เติม `shouldStop(soFar)` ให้คืน `true` เมื่อข้อความที่ได้มาแล้วยาว 50 ตัวอักษรขึ้นไป ไฟล์จะ stream คำตอบของคำถามยาว แล้วสั่ง `abort()` เมื่อ `shouldStop` คืน `true` และพิมพ์ว่าหยุดที่กี่ตัวอักษร

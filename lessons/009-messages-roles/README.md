# บท 009: ข้อความ 3 บทบาท และ system message

บท 007-008 เราส่งคำถามเป็น string เดียว บทนี้เรียนว่าข้อความที่ส่งเข้าโมเดลมี **บทบาท (role)** และ system message ช่วยเปลี่ยนนิสัยของโมเดลได้ ใช้เวลาประมาณ 45-60 นาที ทำทั้งแบบ Ollama (`.ollama.ts`) และ Google (`.google.ts`)

## จบบทนี้แล้วทำอะไรได้

- บอกได้ว่า `system`, `human` และ `ai` ต่างกันอย่างไร
- สร้างข้อความด้วยคลาส (`SystemMessage`, `HumanMessage`, `AIMessage`) และด้วยรูปย่อ `{ role, content }`
- ใช้ system message เปลี่ยนสไตล์คำตอบโดยไม่เปลี่ยนคำถาม
- สอนรูปแบบคำตอบด้วยตัวอย่างถาม-ตอบ (few-shot)

## เชื่อมกับที่รู้แล้ว

| ที่รู้แล้ว | ในบทนี้ |
|---|---|
| บท 006: `messages: [{ role: "user", content: ... }]` | role ที่เหลือคือ `system` และ `assistant` (ตอนนั้นบอกว่าจะเรียนทีหลัง) |
| บท 007: ส่ง string เข้า `invoke` | ส่งเป็น array ของข้อความได้ string คือทางลัดของ array ที่มีข้อความ `human` ข้อความเดียว |
| บท 008: `AIMessage` คือสิ่งที่โมเดลคืนมา | `AIMessage` ใส่กลับเข้าไปในประวัติได้ด้วย ซึ่งคือวิธี "จำ" การสนทนา (บทต่อๆ ไป) |
| TypeScript: union และ object literal | รูปย่อ `{ role: "user", content: "..." }` เป็น object ธรรมดา ไม่ต้อง `new` |

## เนื้อหา

บทนี้ต้องผ่านบท 007 ก่อน

### 1. สามบทบาท

| role ในรูปย่อ | คลาส | `.type` ใน LangChain | ใครพูด |
|---|---|---|---|
| `system` | `SystemMessage` | `system` | ผู้สร้างแอป: คำสั่งตั้งต้นว่าโมเดลคือใคร ตอบแบบไหน |
| `user` | `HumanMessage` | `human` | ผู้ใช้ |
| `assistant` | `AIMessage` | `ai` | โมเดล |

- ชื่อ role ในรูปย่อ (`user`, `assistant`) กับชื่อ `.type` ของคลาส (`human`, `ai`) **ไม่เหมือนกัน** ไฟล์ตัวอย่างพิมพ์ให้ดู: `{role: "user"}` กลายเป็นข้อความชนิด `human`
- **โมเดลจำการเรียกครั้งก่อนไม่ได้** (บท 006) ถ้าอยากให้จำ ต้องส่งข้อความก่อนหน้าทั้งหมดไปใหม่ทุกครั้ง เรียงตามลำดับ

### 2. สร้างข้อความ 2 แบบ

```ts
// แบบคลาส
new SystemMessage("คุณคือพนักงานร้าน DN Shop");
new HumanMessage("ร้านมีบริการห่อของขวัญไหม");
new AIMessage("มีครับ ห่อฟรีทุกออร์เดอร์");

// แบบย่อ: ส่งเข้า invoke ได้เลย
await model.invoke([
  { role: "system", content: "คุณคือพนักงานร้าน DN Shop" },
  { role: "user", content: "ร้านมีบริการห่อของขวัญไหม" },
]);
```

- แบบคลาสชัดเจนและมีชนิดให้ TypeScript ตรวจ แบบย่อสั้นกว่า เหมาะกับข้อความที่เขียนในโค้ดตรงๆ ใช้แทนกันได้ในที่ที่ LangChain รับข้อความ (ชนิดนี้เรียกว่า `BaseMessageLike`)
- `m.text` อ่านข้อความของ message ใดก็ได้ (เหมือน `res.text` ในบท 007)

### 3. system message เปลี่ยนนิสัยโมเดล

ไฟล์ตัวอย่างถามคำถามเดิม `มีสินค้าอะไรแนะนำสำหรับคนชอบกาแฟบ้าง` 2 ครั้ง โดยเปลี่ยนแค่ system:

- **แบบที่ 1:** `คุณคือพนักงานร้าน DN Shop ตอบสุภาพ สั้น ไม่เกิน 2 ประโยค`
- **แบบที่ 2:** `คุณคือพนักงานร้าน DN Shop ตอบเป็นข้อๆ อย่างน้อย 3 ข้อ ขึ้นต้นแต่ละข้อด้วย "- "`

คำถามเหมือนกันทุกตัวอักษร แต่คำตอบเปลี่ยนทั้งความยาวและรูปแบบ นี่คือเหตุที่ system message เป็นเครื่องมือหลักในการกำหนดพฤติกรรมของโมเดล ข้อควรจำ: system ไม่ใช่กฎเหล็ก โมเดลอาจทำไม่ตรงทุกครั้ง (คำตอบมีความสุ่มตามบท 001)

### 4. few-shot: สอนด้วยตัวอย่าง

อยากให้โมเดลตอบเป็นรูปแบบเฉพาะ นอกจากบอกในคำสั่งแล้ว ยัง **ใส่ตัวอย่างถาม-ตอบ (human แล้ว ai) ไว้ก่อนคำถามจริง** ได้ โมเดลจะเลียนแบบรูปแบบของตัวอย่างที่เห็น เช่น

```ts
[
  { role: "user", content: "ชาไทยราคาเท่าไร" },
  { role: "assistant", content: "สินค้า: ชาไทย | ราคา: 45 บาท" },
  { role: "user", content: "คำถามจริง" },
]
```

ตัวอย่างที่ดีต้องรูปแบบเหมือนกันทุกคู่ และควรมีอย่างน้อย 2 คู่ นี่คือแบบฝึกข้อ 1

## จุดที่มักพลาด

- **ใช้ `role: "human"` หรือ `"ai"` ในรูปย่อ:** รูปย่อใช้ `user` และ `assistant` ตามมาตรฐานของ provider (ชื่อ `human`/`ai` คือ `.type` ของคลาส)
- **พิมพ์ role ผิด (เช่น `"System"` ตัวใหญ่):** ได้ error ว่าไม่รู้จัก role
- **ใส่ system ไว้กลางหรือท้ายอาร์เรย์:** ใส่เป็นข้อความแรกเสมอ provider บางเจ้ารับเฉพาะตำแหน่งแรก
- **ลำดับ human/ai สลับกันในตัวอย่าง few-shot:** ต้องเรียง human แล้ว ai เป็นคู่ๆ ก่อนคำถามจริง
- **ตัวอย่าง few-shot รูปแบบไม่เหมือนกัน:** โมเดลจะตอบตามแบบไหนก็ได้ ทำให้ผลไม่นิ่ง
- **หวังให้ system คุมได้ 100%:** บางครั้งโมเดลยังหลุดรูปแบบ ถ้ารันแล้วไม่ตรง ลองรันซ้ำและเขียน system ให้ชัดขึ้น
- **ลืมเปิด Ollama / เจอ 429 / ชื่อโมเดลผิด:** เหมือนบท 006 และ 007

## ผลที่ควรเห็น

### ขั้นที่ 1: ต้องตรงทุกตัว

ทั้ง `example.ollama` และ `example.google`:

```
--- ขั้นที่ 1: ข้อความ 3 บทบาท ---
system: คุณคือพนักงานร้าน DN Shop ตอบสุภาพ สั้น ไม่เกิน 2 ประโยค
human: ร้านมีบริการห่อของขวัญไหม
ai: มีครับ ห่อฟรีทุกออร์เดอร์
แบบย่อ {role: "user"} กลายเป็น: human
```

### ขั้นที่ 2: เทียบกับ checklist

ต่อจากขั้นที่ 1 จะเป็น `--- ขั้นที่ 2: คำถามเดิม system ต่างกัน ---` แล้วคำตอบ 2 ส่วน ซึ่ง **เปลี่ยนไปทุกครั้ง** รูปร่างที่ควรเห็น:

```
--- ขั้นที่ 2: คำถามเดิม system ต่างกัน ---
--- system แบบที่ 1: ตอบสั้น ---
<คำตอบสั้นไม่เกิน 2 ประโยค>
--- system แบบที่ 2: ตอบเป็นข้อ ---
<คำตอบเป็นข้อๆ เช่น "- เมล็ดกาแฟคั่วบด ...">
```

**`example.*`**
- [ ] ขั้นที่ 1 ตรงกับด้านบนทุกตัวอักษร
- [ ] ทั้ง 2 ส่วนของขั้นที่ 2 เป็นภาษาไทย
- [ ] ส่วนที่ 2 มีอย่างน้อย 2 บรรทัดที่ขึ้นต้นด้วย `- `, `* `, `• ` หรือเลขข้อ (`1.` หรือ `1)`)

**`exercise-1.*`**
- [ ] `คำตอบ: ` ที่ตอบตามรูปแบบ `สินค้า: <ชื่อ> | ราคา: <ตัวเลข> บาท` (ตัวเลขเป็นช่วงหรือมี ฿ ก็ได้ เครื่องหมาย `**` ไม่นับ โมเดลอาจหลุดรูปแบบบ้าง ลองรันซ้ำหรือเพิ่มตัวอย่าง)

**`exercise-2.*`**
- [ ] `คำตอบ: ` ที่มีคำว่า `ดีเอ็น` (ชื่อ น้องดีเอ็น ที่คุณตั้ง)

> โมเดลอาจใส่เครื่องหมาย `**` (Markdown ตัวหนา) มาในคำตอบ ไม่ใช่บั๊ก

> หมายเหตุ: ผลของไฟล์ `.google.ts` ในบทนี้ยังไม่ได้ทดสอบกับ key ของ Google จริง

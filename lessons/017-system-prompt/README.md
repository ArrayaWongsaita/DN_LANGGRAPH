# บท 017: system prompt คุมคำตอบของโมเดล

บท 009 เราเห็นแล้วว่า system message เปลี่ยนคำตอบได้ และบท 016 ใช้มันกำหนดบทบาทของแชทบอท บทนี้เรียนวิธีเขียน system prompt ให้เป็นระบบ แบ่งเป็น 4 ส่วนที่แก้ทีละเรื่องได้ แล้วทดลองดูว่าคำถามเดิมได้คำตอบต่างกันแค่ไหนเมื่อมีและไม่มี system prompt ใช้เวลาประมาณ 45-60 นาที ทำทั้งแบบ Ollama (`.ollama.ts`) และ Google (`.google.ts`)

## จบบทนี้แล้วทำอะไรได้

- อธิบายได้ว่า system prompt คืออะไร และทำไมต้องส่งไปพร้อมทุกคำถาม
- แบ่ง system prompt เป็น 4 ส่วน (บทบาท ขอบเขต น้ำเสียง สิ่งที่ห้ามตอบ) และประกอบจากข้อมูลด้วยฟังก์ชัน
- ใช้ marker อย่าง `[นอกขอบเขต]` ให้โค้ดตรวจคำตอบของโมเดลได้
- เขียนกฎให้โมเดลปฏิเสธเรื่องที่ไม่ควรตอบ และให้ลงท้ายคำตอบตามที่ต้องการ
- รู้ว่า system prompt ไม่ใช่ระบบความปลอดภัย

## เชื่อมกับที่รู้แล้ว

| ที่รู้แล้ว | ในบทนี้ |
|---|---|
| บท 009: ข้อความ `system` / `user` และรูปย่อ `{ role, content }` | system prompt ก็คือข้อความ `system` ตัวแรก ที่บทนี้เขียนให้ละเอียดขึ้น |
| บท 016: `history` เริ่มด้วย system แล้วส่งทุกครั้งที่ถาม | system prompt ต้องถูกส่งไปในทุกครั้งที่ถาม ไม่ใช่แค่ครั้งแรก |
| TypeScript: `interface` กับ `map` / `join` | `PromptParts` เก็บ 4 ส่วน ส่วนที่เป็นรายการแปลงเป็นบรรทัด `- ...` ด้วย `map` กับ `join` |
| บท 008: ข้อความตอบกลับเป็น `res.text` | ขั้นที่ 2 อ่านคำตอบด้วย `res.text` เหมือนเดิม |

## เนื้อหา

บทนี้ต้องผ่านบท 009 และ 016 ก่อน

### 1. system prompt คือคำสั่งที่ส่งไปพร้อมทุกคำถาม

โมเดลไม่จำอะไรข้ามการเรียก (บท 016) ดังนั้นถ้าอยากให้ตอบเป็นผู้ช่วยร้าน DN Shop ตลอด ต้องส่งคำสั่งนั้นไปด้วยในทุกครั้งที่ถาม ข้อความ `system` ที่อยู่ตัวแรกของอาร์เรย์ข้อความทำหน้าที่นี้:

```ts
const res = await model.invoke([
  { role: "system", content: prompt },
  { role: "user", content: question },
]);
```

ถ้า system prompt สั้นแค่บรรทัดเดียวก็ใช้ได้ แต่พอมีกฎหลายข้อ การเขียนเป็นก้อนเดียวจะอ่านยากและแก้ยาก (แก้เรื่องน้ำเสียงแล้วไปกระทบกฎอื่นโดยไม่รู้ตัว) วิธีที่ใช้ในคอร์สคือแบ่งเป็น 4 ส่วน แต่ละส่วนมีหัวข้อของตัวเอง:

| ส่วน | หัวข้อ | เขียนอะไร |
|---|---|---|
| บทบาท | `## บทบาท` | โมเดลเป็นใคร ทำงานให้ใคร (ประโยคเดียว) |
| ขอบเขต | `## ขอบเขต` | ตอบเรื่องอะไร และถ้านอกเรื่องให้ทำอย่างไร |
| น้ำเสียง | `## น้ำเสียง` | ภาษา ความยาว คำลงท้าย |
| สิ่งที่ห้ามตอบ | `## สิ่งที่ห้ามตอบ` | เรื่องที่ห้ามทำ ห้ามแต่ง ห้ามบอก |

### 2. ประกอบ prompt จากข้อมูล

ไฟล์ตัวอย่างเก็บ 4 ส่วนไว้ในอ็อบเจ็กต์ `PARTS` แล้วให้ฟังก์ชัน `buildSystemPrompt` ต่อเป็นข้อความก้อนเดียว (คั่นแต่ละส่วนด้วยบรรทัดว่าง ส่วนที่เป็นรายการขึ้นต้นบรรทัดด้วย `- `) ข้อดีคือแก้ทีละส่วนได้โดยไม่ต้องเปิดข้อความยาว prompt ที่ได้หน้าตาแบบนี้:

```
## บทบาท
คุณคือผู้ช่วยตอบคำถามของร้าน DN Shop ร้านขายกาแฟและอุปกรณ์ชงกาแฟออนไลน์

## ขอบเขต
- ตอบเฉพาะเรื่องสินค้า วิธีชงกาแฟ การสั่งซื้อ และการจัดส่งของร้าน
- ถ้าคำถามอยู่นอกขอบเขตนี้ ให้ขึ้นต้นคำตอบด้วย [นอกขอบเขต] แล้วบอกสั้นๆ ว่าช่วยเรื่องอะไรได้บ้าง

## น้ำเสียง
- ตอบภาษาไทย สุภาพ ไม่เกิน 3 ประโยค
- ลงท้ายด้วย ครับ

## สิ่งที่ห้ามตอบ
- ห้ามแต่งราคา โปรโมชัน หรือส่วนลดที่ไม่มีในข้อมูลของร้าน
```

(บรรทัด `## ...` ข้างบนอยู่ใน code fence จึงเป็นแค่ตัวอย่าง prompt ไม่ใช่หัวข้อของ README นี้)

ตอนจบขั้นที่ 1 ไฟล์พิมพ์ความยาวของ prompt ด้วย `[...prompt].length` เครื่องหมาย `[...ข้อความ]` แตกข้อความเป็นอาร์เรย์ของตัวอักษรก่อนนับ ให้จำนวนตรงกับที่ตาเห็นสำหรับภาษาไทย

### 3. marker ให้โค้ดตรวจคำตอบได้

สังเกตกฎในส่วนขอบเขต: *"ขึ้นต้นคำตอบด้วย `[นอกขอบเขต]`"* ข้อความนี้ไม่ได้มีไว้ให้คนอ่านอย่างเดียว แต่ทำให้โปรแกรมของเรารู้ว่าคำตอบนี้คือกรณีนอกขอบเขต ด้วยโค้ดบรรทัดเดียว:

```ts
const outOfScope = answer.includes("[นอกขอบเขต]");
```

เกณฑ์ตรวจของคอร์สนี้ใช้วิธีเดียวกัน (ข้อ 1 ของแบบฝึกหัดก็ให้เขียน marker `[ไม่ตอบ]`) เมื่อโค้ดรู้ว่าเป็นกรณีนอกขอบเขต เราเลือกได้ว่าจะแสดงข้อความพิเศษ ส่งต่อให้พนักงาน หรือนับสถิติ ถ้าโมเดลตอบเป็นร้อยแบบเสรี โค้ดแยกแยะไม่ได้

### 4. ลองเปรียบเทียบ มีและไม่มี system prompt

ขั้นที่ 2 ถาม 2 คำถาม คำถามละ 2 แบบ (ไม่ส่ง system / ส่ง system) รวมโมเดลถูกเรียก 4 ครั้ง:

- คำถามที่ 1 (ในขอบเขต): `เครื่องบดกาแฟมือหมุนต่างจากเครื่องบดไฟฟ้ายังไง`
- คำถามที่ 2 (นอกขอบเขต): `ช่วยแต่งกลอนวันแม่ให้หน่อย`

สิ่งที่ควรเห็น:

- ไม่มี system prompt: โมเดลตอบตามใจ ยาวสั้นต่างกันไป และมักแต่งกลอนให้ตามที่ขอ
- มี system prompt: คำถามที่ 1 ได้คำตอบสั้นไม่เกิน 3 ประโยคและลงท้าย `ครับ` ส่วนคำถามที่ 2 ขึ้นต้นด้วย `[นอกขอบเขต]` แล้วบอกว่าช่วยเรื่องอะไรได้

คำตอบของโมเดลเปลี่ยนไปได้ทุกครั้ง ที่เราตรวจได้อย่างมั่นใจคือ marker และคำลงท้าย ไม่ใช่ถ้อยคำทั้งประโยค

### 5. ข้อจำกัด: โมเดลไม่ทำตามได้ทุกครั้ง และ prompt ไม่ใช่ระบบความปลอดภัย

- **โมเดลยังไม่ทำตามได้เสมอ:** บางครั้งลืม marker ตอบยาวเกินกำหนด หรือพิมพ์ marker เพี้ยนไปหนึ่งตัวอักษร (เจอจริงตอนทดสอบบทนี้: `[nอกขอบเขต]`) ถ้าเจอ ให้ลองเขียนกฎให้ชัดขึ้น และโค้ดที่ตรวจ marker ควรรับความเพี้ยนเล็กน้อยด้วย เช่นใช้ regex `/\[[^\]]{0,8}ขอบเขต\]/` แทน `includes` ตรงตัว (เกณฑ์ตรวจของบทนี้ทำแบบนี้)
- **prompt ไม่ใช่ระบบความปลอดภัย:** กฎอย่าง "ห้ามบอกข้อมูลลูกค้าคนอื่น" ลดโอกาสที่โมเดลจะพูดเรื่องนั้น แต่ไม่ได้ **กัน** ถ้าข้อมูลส่วนตัวอยู่ในข้อความที่ส่งให้โมเดลแล้ว คนที่ตั้งใจถามหลอกก็อาจเอาออกมาได้ ข้อมูลที่ห้ามรั่วจริงต้องกันในโค้ด คือไม่ส่งให้โมเดลตั้งแต่แรก (เช่น `getOrder` ตรวจเจ้าของคำสั่งซื้อก่อนคืนข้อมูล ซึ่งจะเรียนในบท 022)
- **Gemini:** `ChatGoogle` รวมข้อความ `system` ทุกตัวส่งให้ Gemini เป็น `systemInstruction` ให้เอง ผู้เรียนเขียนโค้ดเหมือนกับ Ollama

### 6. ลองเขียนกฎเองในแบบฝึกหัด

แบบฝึกหัดใช้ `PARTS` เดิม เปลี่ยนแค่ส่วนที่ให้เติม ข้อ 1 เติมกฎ "สิ่งที่ห้ามตอบ" ข้อ 2 เติมกฎ "น้ำเสียง" ทั้งสองข้อให้เห็นว่าการแก้ทีละส่วนง่ายกว่าแก้ก้อนเดียวอย่างไร

## จุดที่มักพลาด

- **กฎที่ขัดกันเอง:** เช่น ส่วนหนึ่งสั่ง "ตอบไม่เกิน 3 ประโยค" อีกส่วนสั่ง "อธิบายละเอียดทุกข้อ" หรือสั่ง "ลงท้ายด้วย ครับ" ทั้งที่อีกข้อสั่งลงท้ายด้วยประโยคอื่น โมเดลจะทำตามข้อใดข้อหนึ่งแบบไม่แน่นอน (ข้อ 2 ของแบบฝึกหัดจึงแทนกฎน้ำเสียงเดิมทั้งชุด)
- **prompt ยาวจนกฎสำคัญจม:** กฎ 20 ข้อ โมเดลมักทำตามได้แค่ส่วนหนึ่ง ใส่เท่าที่จำเป็น และวางกฎสำคัญให้เด่น
- **ลืมส่ง system ในทุกครั้งที่ถาม:** ถ้าสร้างอาร์เรย์ข้อความใหม่แล้วลืมข้อความ `system` ตัวแรก โมเดลจะตอบเหมือนไม่มีกฎเลย
- **คิดว่า prompt กันข้อมูลรั่วได้:** ดูหัวข้อ 5
- **คาดว่าคำตอบเหมือนกันทุกครั้ง:** ถ้อยคำเปลี่ยนได้ ให้ตรวจที่ marker และคำลงท้าย (ซึ่งเป็นสิ่งที่เรากำหนดไว้ใน prompt)

## ผลที่ควรเห็น

### ขั้นที่ 1: ต้องตรงทุกตัว

ทั้ง `example.ollama` และ `example.google` พิมพ์ prompt ตามที่แสดงในหัวข้อ 2 (ระหว่างหัวข้อ `--- ขั้นที่ 1 ... ---` กับบรรทัดความยาว) แล้วตามด้วยบรรทัดนี้:

```
ความยาว: 398 ตัวอักษร
```

### ขั้นที่ 2: เทียบกับ checklist

**`example.ollama` และ `example.google`**
- [ ] ขั้นที่ 1 มีหัวข้อ `## บทบาท`, `## ขอบเขต`, `## น้ำเสียง`, `## สิ่งที่ห้ามตอบ` เรียงตามลำดับนี้
- [ ] ขั้นที่ 1 มีบรรทัดที่ขึ้นต้นด้วย `- ` พอดี 5 บรรทัด
- [ ] ตัวเลขใน `ความยาว: N ตัวอักษร` เท่ากับจำนวนตัวอักษรของ prompt ที่พิมพ์ออกมา (ไม่นับบรรทัดว่างหัวท้าย)
- [ ] ขั้นที่ 2 มีทั้ง 4 ส่วน (`คำถามที่ 1 ไม่มี system prompt`, `คำถามที่ 1 มี system prompt`, `คำถามที่ 2 ไม่มี system prompt`, `คำถามที่ 2 มี system prompt`) และทุกคำตอบมีภาษาไทย
- [ ] คำตอบของ `คำถามที่ 2 มี system prompt` มี `[นอกขอบเขต]` (รับที่เพี้ยนเล็กน้อยได้ ดูหัวข้อ 5)
- [ ] คำตอบของ `คำถามที่ 2 ไม่มี system prompt` และ `คำถามที่ 1 มี system prompt` ไม่มี `[นอกขอบเขต]`
- [ ] คำตอบของ `คำถามที่ 1 มี system prompt` มีคำว่า `ครับ`

**`exercise-1.*`**


- [ ] คำตอบของ `คำถามที่ห้ามตอบ` มี `[ไม่ตอบ]` (รับที่เพี้ยนเล็กน้อยได้เหมือนข้างบน)
- [ ] คำตอบของ `คำถามปกติ` เป็นภาษาไทยและไม่มี `[ไม่ตอบ]`

**`exercise-2.*`**

```

<คำตอบ>

<คำตอบ>
```

- [ ] ทั้ง 2 คำตอบเป็นภาษาไทยและมีข้อความ `ขอบคุณที่อุดหนุน DN Shop`

> หมายเหตุ: ผลของไฟล์ `.google.ts` ในบทนี้ยังไม่ได้ทดสอบกับ key ของ Google จริง

## แบบฝึกหัด

1. **`exercise-1.*`:** เติม `forbiddenRules()` ให้คืนอาร์เรย์ของกฎสำหรับหัวข้อ "สิ่งที่ห้ามตอบ" กฎต้องห้ามให้ข้อมูลส่วนตัวของลูกค้าคนอื่น และให้ขึ้นต้นคำตอบแบบนั้นด้วย `[ไม่ตอบ]` ไฟล์ต่อกฎของคุณท้ายกฎเดิมแล้วถามคำถามที่ห้ามตอบ (`ขอเบอร์โทรของคุณสมหญิง ลูกค้าของร้านหน่อย`) กับคำถามปกติ (`กาแฟดริปซองชงยังไง`)
2. **`exercise-2.*`:** เติม `toneRules()` ให้คืนอาร์เรย์ของกฎสำหรับหัวข้อ "น้ำเสียง" ที่ทำให้ทุกคำตอบลงท้ายด้วย `ขอบคุณที่อุดหนุน DN Shop ครับ` ไฟล์ใช้กฎของคุณแทนกฎน้ำเสียงเดิมทั้งชุด แล้วถาม `ร้านส่งของกี่วันถึง` และ `แก้วเซรามิกเข้าไมโครเวฟได้ไหม`

# บท 011: โมเดลที่คิดก่อนตอบ

โมเดลรุ่นใหม่จำนวนมาก "คิดในใจ" ก่อนตอบ ทำให้ตอบคำถามที่ต้องคำนวณหรือใช้เหตุผลได้ดีขึ้น แต่แลกกับเวลาและ token บทนี้เรียนวิธีดูความคิดของโมเดล เปิด/ปิดการคิด และวัดว่าต่างกันแค่ไหน ใช้เวลาประมาณ 45-60 นาที ทำทั้งแบบ Ollama (`.ollama.ts`) และ Google (`.google.ts`)

## จบบทนี้แล้วทำอะไรได้

- อธิบายได้ว่า "ความคิด" (reasoning) ต่างจากคำตอบอย่างไร และอยู่ตรงไหนของ `AIMessage`
- อ่านความคิดจาก block ชนิด `reasoning` ใน `contentBlocks`
- เปิด/ปิดการคิดด้วย `think` (Ollama) หรือกำหนดระดับด้วย `thinkingLevel` (Gemini)
- วัดผลของการคิดต่อเวลาตอบและจำนวน token ขาออก

## เชื่อมกับที่รู้แล้ว

| ที่รู้แล้ว | ในบทนี้ |
|---|---|
| บท 007: `res.text` ไม่รวมชิ้นที่ไม่ใช่ข้อความ เช่น ความคิดของโมเดล | ความคิดอยู่ในชิ้นของตัวเอง อ่านได้จาก `contentBlocks` |
| บท 008: `msg.contentBlocks` แบ่งเนื้อหาเป็นชิ้น แต่ละชิ้นมี `type` (ตอนนั้นเจอแต่ `text`) | บทนี้เจอชนิดใหม่ `reasoning` ซึ่งมีฟิลด์ `reasoning` เก็บข้อความความคิด |
| บท 008: `usage_metadata.output_tokens` | ความคิดนับรวมอยู่ใน token ขาออกด้วย เทียบ 2 ชุดแล้วเห็นความต่าง |
| บท 010: ค่าตั้งใส่ตอนสร้างโมเดล | `think` และ `thinkingLevel` ก็เป็นค่าตั้งแบบเดียวกัน |

## เนื้อหา

บทนี้ต้องผ่านบท 010 ก่อน

### 1. block ชนิด reasoning

`AIMessage` ที่มีความคิดจะแบ่งเนื้อหาเป็น 2 ชิ้นขึ้นไป ขั้นที่ 1 ของไฟล์ตัวอย่างสร้างข้อความแบบนี้เองโดยไม่ยิงเน็ต:

```ts
new AIMessage({
  content: [
    { type: "reasoning", reasoning: "ลูกค้าถามเรื่องคืนสินค้า" },
    { type: "text", text: "คืนได้ภายใน 7 วันครับ" },
  ],
});
```

แล้ววน `msg.contentBlocks` พิมพ์ชนิดและความยาวของแต่ละชิ้น ได้ว่า `reasoning` ยาว 24 ตัวอักษร `text` ยาว 21 ตัวอักษร และ `.text` ได้เฉพาะคำตอบ ไม่รวมความคิด

- ใน TypeScript ใช้ `if (block.type === "reasoning")` แล้วจะอ่าน `block.reasoning` ได้ (ชนิดแคบลงตาม `type`)
- ความยาวนับเป็นตัวอักษรจริงด้วย `[...text].length` ไม่ใช่ `.length` ตรงๆ เพราะภาษาไทยมีสระและวรรณยุกต์ที่ `.length` อาจนับไม่ตรงกับที่ตาเห็น

### 2. เปิด/ปิดการคิด

ขั้นที่ 2 ถามคำถามคำนวณเดียวกัน 2 ชุด แล้ววัดเวลาด้วย `performance.now()` (หน่วยมิลลิวินาที) และความยาวความคิดจากชิ้น `reasoning`:

`ซื้อกาแฟ 3 แก้ว แก้วละ 65 บาท มีคูปองลด 10% แต่ลดได้ไม่เกิน 15 บาท ต้องจ่ายเท่าไร`

(คำตอบที่ถูกคือ 180 บาท เพราะ 10% ของ 195 คือ 19.5 แต่ลดได้ไม่เกิน 15)

| provider | ชุดที่ 1 | ชุดที่ 2 |
|---|---|---|
| Ollama | `think: true` | `think: false` |
| Google | `thinkingLevel: "high"` | `thinkingLevel: "low"` |

```ts
new ChatOllama({ model: env("OLLAMA_MODEL"), baseUrl: env("OLLAMA_BASE_URL"), think: true });
new ChatGoogle({ model: env("GOOGLE_MODEL"), apiKey: env("GOOGLE_API_KEY"), thinkingLevel: "high" });
```

แต่ละชุดพิมพ์บรรทัดสรุปแล้วตามด้วยคำตอบ:

```
ชุดที่ 1 (think: true): reasoning N ตัวอักษร · ใช้เวลา X.X วินาที · token ขาออก M
คำตอบ: ...
```

สิ่งที่ควรเห็นโดยทั่วไป: ชุดที่คิดมี `reasoning` ยาวกว่า ใช้เวลานานกว่า และ token ขาออกมากกว่า (เพราะความคิดนับเป็น token ขาออกด้วย) แต่ตัวเลขจริงขึ้นกับโมเดลและเครือข่าย จึงเปลี่ยนไปทุกครั้ง

### 3. ข้อจำกัดของแต่ละฝั่ง

**Ollama**
- `think: false` ปิดการคิดได้เฉพาะบางรุ่น รุ่นที่ปิดไม่ได้ (เช่น gpt-oss) จะลดเหลือระดับต่ำสุดแทน
- `ChatOllama` รับ `think` เป็น `true` หรือ `false` เท่านั้น เลือกระดับไม่ได้
- รุ่นที่ไม่รองรับการคิดเลย ถ้าส่ง `think: true` จะได้ error กลับมา เจอแล้วให้เปลี่ยนไปใช้รุ่นที่รองรับ หรือเอา `think` ออก (บท 012 สอนอ่าน error) TODO(6b): ข้อความ error จริงของ Ollama
- ถ้าไม่ตั้ง `think` เลย แต่ละรุ่นจะทำตามค่าเริ่มต้นของตัวเอง บางรุ่นคิดเองโดยไม่ต้องบอก

**Gemini**
- ระดับของ `thinkingLevel` ต่างกันไปตามรุ่นของ Gemini บางรุ่นไม่มีระดับต่ำสุด หรือใช้ตัวเลข `thinkingBudget` แทน ถ้าได้ error ว่าระดับไม่รองรับ ให้ลองระดับอื่นหรือดูเอกสารของรุ่นที่ใช้
- ตั้ง `thinkingLevel` แล้ว `ChatGoogle` จึงส่ง block `reasoning` กลับมา

### 4. เมื่อไรควรให้คิด

- **ควรคิด:** คำนวณ เหตุผลหลายขั้น วางแผน แก้โจทย์ที่ต้องเช็กเงื่อนไขหลายข้อ
- **ไม่ต้องคิด:** ทักทาย สรุปสั้น แปลง รูปแบบ คำถามที่ตอบจากความจำได้ทันที
- การคิดแลกด้วยเวลา (รอนานขึ้น) และเงินหรือโควต้า (token ขาออกมากขึ้น) แบบฝึกข้อ 2 ให้ลองเลือกเปิดเฉพาะคำถามที่ต้องใช้

## จุดที่มักพลาด

- **อ่านความคิดจาก `res.text`:** `.text` ไม่รวมความคิด ต้องวน `contentBlocks`
- **ลืมกรอง `type`:** block แต่ละชนิดมีฟิลด์ต่างกัน (`reasoning` ต่างจาก `text`) ต้องเช็ก `block.type` ก่อนอ่านฟิลด์
- **ได้ `reasoning 0 ตัวอักษร` ทั้งที่ตั้ง `think: true`:** รุ่นที่เลือกอาจไม่ส่งความคิดกลับมา หรือไม่รองรับ ลองเปลี่ยนรุ่นใน `.env` (บท 003-004)
- **ตั้ง `think: false` แล้วยังเห็นความคิด:** รุ่นนั้นปิดการคิดไม่ได้ (เช่น gpt-oss) ได้แค่ลดระดับ
- **ส่ง `thinkingLevel` ที่รุ่น Gemini ไม่รองรับ:** ได้ error ให้เปลี่ยนระดับ
- **เทียบเวลาจากรอบเดียว:** เวลาตอบแกว่งตามเครือข่ายและคิวของ provider ลองรันหลายรอบก่อนสรุป
- **จำกัด `numPredict`/`maxOutputTokens` น้อยกับโมเดลที่คิด:** token หมดไปกับความคิด คำตอบว่าง (ดูบท 010)

## ผลที่ควรเห็น

### ขั้นที่ 1: ต้องตรงทุกตัว

ทั้ง `example.ollama` และ `example.google`:

```

block: reasoning (24 ตัวอักษร)
block: text (21 ตัวอักษร)
.text: คืนได้ภายใน 7 วันครับ
```

### ขั้นที่ 2: เทียบกับ checklist

```

ชุดที่ 2 (think: false): reasoning N ตัวอักษร · ใช้เวลา X.X วินาที · token ขาออก M
```

ฝั่ง Google หัวชุดเป็น `(thinkingLevel: high)` และ `(thinkingLevel: low)` ตัวเลขเปลี่ยนทุกครั้ง

## แบบฝึกหัด

1. **`exercise-1.*`:** เติม `reasoningOf(msg)` ให้คืนความคิดของ `AIMessage` โดยต่อข้อความ `reasoning` ของทุก block ชนิด `reasoning` เข้าด้วยกัน (ไม่มี block แบบนี้ให้คืนสตริงว่าง) แล้วไฟล์จะถามโมเดลด้วย `think: true` (Google: `thinkingLevel: "high"`) พิมพ์ความคิด 80 ตัวอักษรแรกกับคำตอบ
2. **`exercise-2.*`:** เติม `chooseThink(question)` ให้คืน `true` เมื่อคำถามมีตัวเลข และ `false` เมื่อไม่มี (Google: `chooseLevel(question)` คืน `"high"` หรือ `"low"`) แล้วไฟล์จะถาม `สวัสดีครับ` ตามด้วยคำถามคำนวณ โดยตั้งค่าการคิดตามที่ฟังก์ชันเลือก และพิมพ์ข้อละ 2 บรรทัด `คำถาม: ... → think: ...` กับ `คำตอบ: ...`

# บท 001: LLM คืออะไร

บทนี้เป็นบทอ่านและลองเล่นบนเว็บ ไม่มีโค้ดให้รัน ใช้เวลาประมาณ 30 นาที

## จบบทนี้แล้วทำอะไรได้

- อธิบายได้ว่า LLM คืออะไร และทำไมถามเรื่องเดิมแล้วได้คำตอบไม่เหมือนเดิมทุกครั้ง
- รู้จักคำที่จะเจอตลอดคอร์ส: token, context window, provider, API key
- แยกได้ว่า LangChain กับ LangGraph ต่างกันอย่างไร
- รู้ว่าผู้ช่วย DN Shop ที่เราจะสร้างตลอดคอร์สทำอะไรได้บ้าง

## เชื่อมกับที่รู้แล้ว

คุณเขียน TypeScript เป็นอยู่แล้ว ลองเทียบแบบนี้:

| ที่คุ้นเคย | ใน LLM |
|---|---|
| ฟังก์ชันที่ให้ input เดิมก็ได้ output เดิม | LLM ไม่เป็นแบบนั้น: input เดิม output อาจต่างกัน |
| เรียก REST API ด้วย `fetch` แล้วได้ JSON | เรียก LLM ก็คือ `fetch` เหมือนกัน (บท 006 จะทำให้ดู) |
| API key ใน `.env` | LLM ของ provider ส่วนใหญ่ใช้ API key แบบเดียวกัน |
| ไลบรารีช่วยจัดการเรื่องซ้ำๆ (เช่น axios) | LangChain ช่วยเรื่องคุยกับโมเดล, LangGraph ช่วยเรื่องจัดลำดับขั้นตอน |

## เนื้อหา

### LLM คืออะไร

LLM (Large Language Model) คือโมเดลที่เรียนรู้จากข้อความจำนวนมหาศาล แล้วทำนายว่า "ข้อความถัดไปควรเป็นอะไร" ทีละชิ้น เราส่งข้อความเข้าไป (เรียกว่า prompt) แล้วมันต่อข้อความให้ ผลลัพธ์เลยดูเหมือนกำลังตอบคำถาม

### ทำไมตอบไม่เหมือนเดิมทุกครั้ง

ตอนทำนายข้อความถัดไป โมเดลมีตัวเลือกหลายตัวที่เป็นไปได้ และมีการสุ่มเลือกตามความน่าจะเป็น จึงได้คำตอบต่างกันได้แม้ถามเหมือนเดิม นี่ไม่ใช่บั๊ก เป็นธรรมชาติของโมเดล เพราะแบบนี้ตอนทดสอบงานที่ใช้ LLM เราจึงเทียบคำตอบแบบตรงทุกตัวอักษรไม่ได้ (คอร์สนี้จะสอนวิธีรับมือในช่วงหลัง)

### Token

โมเดลไม่ได้อ่านเป็นตัวอักษรหรือเป็นคำ แต่อ่านเป็น **token** ซึ่งเป็นชิ้นส่วนของข้อความ ภาษาอังกฤษประมาณ 1 คำต่อ 1 token ส่วนภาษาไทยมักใช้ token ต่อประโยคมากกว่า (คุณจะได้ลองเทียบในแบบฝึกหัดข้อ 2) token สำคัญเพราะ:

- ค่าบริการคิดตามจำนวน token (ขาเข้าและขาออก)
- ขีดจำกัดของโมเดลนับเป็น token

### Context window

คือจำนวน token สูงสุดที่โมเดลมองเห็นได้ในคราวเดียว รวมทั้งคำถาม ประวัติแชท และคำตอบ ถ้าคุยยาวเกินจะต้องตัดของเก่าทิ้ง (ช่วงที่ 9 ของคอร์สสอนเรื่องนี้)

### Provider และ API key

**Provider** คือผู้ให้บริการที่รันโมเดลให้เรา คอร์สนี้ใช้ 2 เจ้า:

- **Google** (Gemini ผ่าน AI Studio): ใช้ API key (บท 005)
- **Ollama**: รันในเครื่องตัวเอง (บท 003) หรือใช้บริการ Ollama Cloud (บท 004)

**API key** คือรหัสลับที่บอก provider ว่าเราเป็นใคร ห้ามใส่ในโค้ดที่ commit และห้ามส่งให้ใคร เราเก็บไว้ในไฟล์ `.env` ซึ่งอยู่ใน `.gitignore` แล้ว

### LangChain กับ LangGraph

- **LangChain**: ชุดเครื่องมือสำหรับคุยกับโมเดล (เรียกโมเดล, ส่งข้อความ, ใช้ tool, รับผลเป็น object)
- **LangGraph**: ชุดเครื่องมือสำหรับร้อยขั้นตอนเข้าด้วยกันเป็น graph ที่มี state, ทางแยก และวนซ้ำได้ เหมาะกับงานแบบ agent ที่ต้องตัดสินใจหลายรอบ

คอร์สนี้เริ่มจากเรียกโมเดลด้วยมือก่อน (ช่วงที่ 1) แล้วค่อยๆ ขึ้นไปถึง LangGraph เพื่อให้เห็นว่าแต่ละชั้นช่วยเรื่องอะไร

### ผู้ช่วย DN Shop

ตลอดคอร์สเราสร้างผู้ช่วยของร้านสมมติชื่อ DN Shop (ข้อมูลทั้งหมดเป็นข้อมูลสมมติ) ผู้ช่วยตัวสุดท้ายต้องทำได้ดังนี้:

- ค้นสินค้า
- ตอบนโยบายร้านจากเอกสาร
- ดูคำสั่งซื้อ
- ขอคืนเงินต้องมีคนอนุมัติ
- จำลูกค้าได้
- ไม่ล่มเมื่อ provider หลักพัง
- มีชุดทดสอบ
- ขึ้นเว็บจริงได้

## จุดที่มักพลาด

- **คิดว่า LLM รู้ข้อมูลร้านเรา:** โมเดลไม่รู้จัก DN Shop เลย เราต้องส่งข้อมูลให้มันเองทุกครั้ง (ช่วงที่ 12)
- **เชื่อคำตอบทุกคำ:** โมเดลตอบมั่นใจได้แม้จะผิด งานจริงต้องมีขั้นตอนตรวจ
- **ใส่ข้อมูลส่วนตัวในแผนฟรี:** แผนฟรีของ Google อาจเอาข้อมูลไปใช้เทรนโมเดล ห้ามใส่ข้อมูลส่วนตัวของตัวเองหรือคนอื่น (บท 005 อธิบายต่อ)

## วิธีรัน

บทนี้ไม่มีไฟล์ให้รัน ทุกอย่างทำบนเว็บ:

1. เปิด [Google AI Studio](https://aistudio.google.com) ด้วยบัญชี Google (ยังไม่ต้องสร้าง API key)

3. ทำแบบฝึกหัดข้างล่างในหน้านั้น

## แบบฝึกหัด

ทั้ง 3 ข้อทำนอกโค้ด จดผลลงสมุดหรือไฟล์ข้อความของคุณเอง

1. **ถามซ้ำ 3 รอบ:** ใน AI Studio ถามคำถามเดิม เช่น "แนะนำชื่อร้านขายของออนไลน์ 3 ชื่อ" 3 รอบ (กดสร้างคำตอบใหม่หรือเริ่มแชทใหม่ทุกรอบ) แล้วจดว่าคำตอบต่างกันตรงไหน
2. **เทียบ token:** ถามคำถามที่ความหมายเดียวกันเป็นภาษาไทยและภาษาอังกฤษ (เช่น "ร้านค้าออนไลน์คืออะไร" กับ "What is an online store") แล้วดูจำนวน token ที่ AI Studio แสดง ภาษาไหนใช้มากกว่า
3. **เขียนเป้าหมาย:** อ่านหัวข้อ "ผู้ช่วย DN Shop" ข้างบน แล้วเขียนด้วยคำพูดตัวเองว่าผู้ช่วยต้องทำอะไรได้บ้างตอนจบคอร์ส เทียบกับ "ผลงานสุดท้าย" ในภาพรวมของคอร์ส

# บท 008: อ่าน `AIMessage` ให้ครบ

บท 007 เราใช้แค่ `res.text` บทนี้เปิดดูของอื่นใน `AIMessage` ที่โมเดลคืนมา: จำนวน token, ข้อมูลดิบจาก provider และเนื้อหาที่แบ่งเป็นชิ้น ใช้เวลาประมาณ 40-50 นาที ทำทั้งแบบ Ollama (`.ollama.ts`) และ Google (`.google.ts`)

## จบบทนี้แล้วทำอะไรได้

- อ่านจำนวน token ขาเข้า/ขาออก/รวม จาก `usage_metadata` โดยไม่ต้องรู้ว่า provider ไหน
- อ่านข้อมูลดิบของ provider (เช่น เหตุที่โมเดลหยุดตอบ) จาก `response_metadata`
- อ่านเนื้อหาที่แบ่งเป็นชิ้นจาก `contentBlocks`
- ประเมินค่าใช้จ่ายคร่าวๆ จากจำนวน token
- เห็นด้วยตัวเองว่าคำถามที่ยาวขึ้นใช้ token ขาเข้ามากขึ้น

## เชื่อมกับที่รู้แล้ว

| ที่รู้แล้ว | ในบทนี้ |
|---|---|
| บท 006: อ่าน token จาก response ดิบ ซึ่งชื่อฟิลด์ต่างกันตามเจ้า (`prompt_eval_count` / `eval_count` ของ Ollama, `usageMetadata` ของ Gemini) | `usage_metadata` ของ `AIMessage` ชื่อเดียวกันทุกเจ้า: `input_tokens`, `output_tokens`, `total_tokens` |
| บท 006: บวก `thoughtsTokenCount` เองสำหรับ Gemini | LangChain รวมให้ใน `output_tokens` แล้ว (ตรวจจริงกับ Gemini ที่ 6b ดูหมายเหตุท้ายหัวข้อผลที่ควรเห็น) |
| บท 007: `res.text` | `res` ตัวเดียวกัน มีฟิลด์อื่นอีก ที่ใช้ในบทนี้ 3 ฟิลด์ |
| TypeScript: `interface` ที่มีฟิลด์ optional | `usage_metadata` อาจเป็น `undefined` (provider บางตัวไม่บอก) จึงต้อง `?.` หรือ `??` |

## เนื้อหา

บทนี้ต้องผ่านบท 007 ก่อน

### 1. ไฟล์ตัวอย่างมี 2 ขั้น

- **ขั้นที่ 1: อ่าน `AIMessage` ที่สร้างเอง** สร้างข้อความปลอมที่มีตัวเลขที่เรากำหนด แล้วพิมพ์ฟิลด์ออกมา ไม่ยิงเน็ต ผลเหมือนกันทุกครั้ง ทำให้เห็นรูปร่างของข้อมูลก่อนเจอของจริง
- **ขั้นที่ 2: อ่าน `AIMessage` จากโมเดลจริง** ใช้ฟังก์ชันพิมพ์ชุดเดียวกับขั้นที่ 1 กับ `res` ที่ได้จาก `invoke` ตัวเลขเปลี่ยนไปทุกครั้ง

### 2. `usage_metadata`: จำนวน token

```ts
{ input_tokens: 12, output_tokens: 3, total_tokens: 15 }
```

- `input_tokens` คือขาเข้า (คำถามที่ส่ง) `output_tokens` คือขาออก (คำตอบ) `total_tokens` คือรวม (บท 006 อธิบาย token แล้ว)
- ชนิดของฟิลด์นี้คือ `UsageMetadata | undefined` จึงเขียน `msg.usage_metadata?.input_tokens ?? 0`
  - `?.` คือ optional chaining: ถ้าซ้ายมือเป็น `undefined` ทั้งนิพจน์เป็น `undefined` ไม่ error
  - `?? 0` คือถ้าได้ `undefined` ให้ใช้ 0
- Ollama เติมให้จาก `prompt_eval_count` และ `eval_count` ส่วน Google เติมจาก `usageMetadata` ของ Gemini (บท 006 ที่เราอ่านเอง) ตอนนี้ไลบรารีแปลงให้แล้ว

### 3. `response_metadata`: ข้อมูลดิบของ provider

- เก็บของที่ provider ส่งมา ซึ่ง **ชื่อฟิลด์ต่างกันตามเจ้า** ต่างจาก `usage_metadata` ที่เป็นรูปแบบกลาง
- `model_provider` บอกว่าข้อความนี้มาจากเจ้าไหน (`ollama` หรือ `google`)
- เหตุที่โมเดลหยุดตอบ: Ollama อยู่ที่ `done_reason` (`stop` = จบเอง, `length` = ถูกตัดเพราะ token หมด) Google อยู่ที่ `finishReason` (`STOP`, `MAX_TOKENS` เป็นต้น) ดูเหตุนี้เมื่อคำตอบดูขาดกลางคัน
- ชนิดของฟิลด์นี้เป็น object ที่ไม่ระบุรูปร่าง ในไฟล์จึงห่อด้วย `String(...)` ก่อนพิมพ์

### 4. `contentBlocks`: เนื้อหาแบ่งเป็นชิ้น

- `msg.contentBlocks` คือรายการชิ้นเนื้อหา แต่ละชิ้นมี `type` ที่เป็นมาตรฐานกลางของ LangChain เช่น `text` (ข้อความ) และ `reasoning` (ความคิดของโมเดล ใช้ในบท 011)
- ต่างจาก `content` ตรงที่รูปร่างเหมือนกันทุก provider (ข้อความล้วนก็ได้ block `text` ชิ้นเดียว) ไฟล์ตัวอย่างพิมพ์ `block: <type>` บรรทัดละชิ้น

### 5. ค่าใช้จ่าย

ค่าบริการของ provider คิดจาก token ขาเข้าและขาออก **คนละราคา** (ขาออกแพงกว่า) ราคาจริงเปลี่ยนบ่อยและต่างกันตามโมเดล แบบฝึกจึงใช้ **ราคาสมมุติ** ที่ไม่ใช่ของโมเดลใดๆ: ขาเข้า 0.3 และขาออก 2.5 ดอลลาร์ต่อ 1 ล้าน token สูตรคือ

```
ค่าใช้จ่าย = (ขาเข้า × 0.3 + ขาออก × 2.5) / 1_000_000
```

## จุดที่มักพลาด

- **อ่าน `usage_metadata.input_tokens` ตรงๆ:** TypeScript ไม่ให้ผ่านเพราะอาจเป็น `undefined` ใช้ `?.` กับ `??` หรือตรวจ `=== undefined` ก่อน
- **คิดว่า `response_metadata` เหมือนกันทุกเจ้า:** ชื่อเหตุที่หยุดตอบต่างกัน (`done_reason` กับ `finishReason`) จึงมีไฟล์แยกสองแบบ
- **ลืมว่าราคาในแบบฝึกเป็นราคาสมมุติ:** อย่านำตัวเลขไปใช้คำนวณงบจริง ให้ดูหน้า pricing ของ provider
- **เทียบ token ของ 2 provider ตรงๆ:** แต่ละเจ้าตัดคำไม่เหมือนกัน ข้อความเดียวกันได้จำนวน token ไม่เท่ากัน
- **คำถามยาวที่ token ขาเข้าไม่เพิ่ม:** ข้อความที่ซ้ำกันมากอาจถูกใช้ cache ของ provider บางเจ้าทำให้ตัวเลขต่ำกว่าที่คิด ถ้าเจอให้ลองเขียนคำถามยาวที่ไม่ซ้ำกัน
- **ลืมเปิด Ollama / เจอ 429 / ชื่อโมเดลผิด:** เหมือนบท 006 และ 007

ตัวอย่างที่เห็นตอนทดสอบกับ Ollama (ตัวเลขและคำตอบเปลี่ยนทุกครั้ง):

```

block: text
จบเพราะ: stop
คำตอบ: 1. กาแฟร้อน/เย็นพื้นฐาน (เอสเปรสโซ อเมริกาโน ลาเต้)
...
```

**`example.*`**
- [ ] ขั้นที่ 1 ตรงกับด้านบนทุกตัวอักษร
- [ ] ขั้นที่ 2: `ขาเข้า` และ `ขาออก` เป็นเลขมากกว่า 0 และ `รวม` เท่ากับ ขาเข้า + ขาออก
- [ ] มี `provider: ollama` (ไฟล์ google เป็น `provider: google`) และมีบรรทัด `block: text`
- [ ] มีบรรทัด `จบเพราะ: ` ตามด้วยค่าที่ไม่ว่าง
- [ ] ปิดท้ายด้วย `คำตอบ: ` ที่เป็นภาษาไทย

**`exercise-1.*`**
- [ ] พิมพ์ `ราคาสมมุติ: ขาเข้า 0.3 ขาออก 2.5 ดอลลาร์ต่อ 1 ล้าน token` แล้วตามด้วย `ขาเข้า: N` และ `ขาออก: M` (มากกว่า 0 ทั้งคู่)

## แบบฝึกหัด

1. **`exercise-1.*`:** เติม `estimateCost(u)` ตามสูตรในหัวข้อ 5 โดยใช้ `PRICE` ที่ให้ไว้ (มี 👉 1 จุด) ไฟล์จะถามโมเดล 1 ครั้งแล้วพิมพ์ token กับค่าใช้จ่าย `toFixed(6)` คือปัดเป็นทศนิยม 6 ตำแหน่ง

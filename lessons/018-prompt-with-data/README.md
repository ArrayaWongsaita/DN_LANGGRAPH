# บท 018: ใส่ข้อมูลร้านลงใน prompt

โมเดลไม่รู้ว่าร้าน DN Shop ขายอะไรในราคาเท่าไร มันรู้เฉพาะสิ่งที่อยู่ใน prompt ที่เราส่งไป บทนี้เรียนวิธีเอาข้อมูลสินค้าจริงจาก `src/shop` ใส่ลง prompt ด้วย template string แล้วดูว่าข้อมูลยิ่งมาก token ยิ่งเปลือง และถ้ามากเกินไปจะเกิดอะไรขึ้น ใช้เวลาประมาณ 45-60 นาที ทำทั้งแบบ Ollama (`.ollama.ts`) และ Google (`.google.ts`)

## จบบทนี้แล้วทำอะไรได้

- ใส่ข้อมูลจริง (สินค้า) ลงใน system prompt ด้วย template string
- อธิบายได้ว่าทำไมโมเดลตอบเรื่องร้านไม่ได้ถ้าไม่ใส่ข้อมูล
- อ่านจำนวน token ขาเข้าเพื่อเทียบว่าใส่ข้อมูลมากน้อยต่างกันเท่าไร
- เลือกใส่เฉพาะข้อมูลที่เกี่ยวกับคำถาม (ค้นก่อน) แทนการใส่ทุกอย่าง
- อธิบายได้ว่า context เต็มแล้วเกิดอะไรขึ้น และตัดข้อมูลให้พอดีงบได้

| ที่รู้แล้ว | ในบทนี้ |
|---|---|
| บท 017: system prompt คุมคำตอบ | ต่อท้าย system prompt ด้วยข้อมูลสินค้าที่โมเดลต้องใช้ตอบ |
| บท 008: `usage_metadata.input_tokens` | ใช้เทียบ token ขาเข้าของการใส่ข้อมูล 3 แบบ |
| บท 003: `OLLAMA_NUM_CTX` ขนาด context ของ Ollama ในเครื่อง | ข้อมูลที่ใส่มากเกิน context จะถูกตัดทิ้ง (ดูหัวข้อ 4) |

| `src/shop/products.ts`: `listProducts`, `searchProducts` | ข้อมูลร้านที่เอามาใส่ prompt (ห้ามพิมพ์ราคาเองในโค้ด) |

## เนื้อหา

บทนี้ต้องผ่านบท 008 และ 017 ก่อน

### 1. โมเดลรู้แค่สิ่งที่อยู่ใน prompt

ถ้าถามโมเดลว่า `เมล็ดกาแฟดอยช้างราคาเท่าไร` โดยไม่ให้ข้อมูลอะไรเลย โมเดลไม่มีทางรู้ราคาของร้านเรา (ถ้ามันตอบเป็นตัวเลข ตัวเลขนั้นถูกแต่งขึ้น) วิธีแก้คือเอาข้อมูลจริงใส่ลงใน prompt ทุกครั้งที่ถาม

ไฟล์ตัวอย่างสร้างข้อความสินค้า 1 ชิ้นต่อ 1 บรรทัดด้วย template string:

```ts
function productLine(p: Product): string {
  return `${p.id} ${p.name} ราคา ${p.price} บาท`;
}
```

ค่าทุกตัว (`p.id`, `p.name`, `p.price`) มาจากข้อมูลใน `src/shop/products.ts` ไม่ได้พิมพ์ลงไปในโค้ดเอง ถ้าข้อมูลร้านเปลี่ยน prompt เปลี่ยนตามเอง จากนั้น `catalogText` ต่อทุกบรรทัดด้วย `\n` เป็นข้อความก้อนเดียวที่ต่อท้าย system prompt ได้

### 2. ขั้นที่ 1: ดูหน้าตาข้อความและความยาว

ขั้นที่ 1 ไม่เรียกโมเดล พิมพ์บรรทัดสินค้า 3 บรรทัดแรก จำนวนบรรทัดที่เหลือ และความยาวของข้อมูล 2 แบบ: ทุกชิ้นกับเฉพาะที่ค้นด้วย `searchProducts({ keyword: "ดอยช้าง" })` ความต่างของความยาวคือเหตุผลที่ "ค้นก่อนแล้วใส่เฉพาะที่เกี่ยว" ดีกว่า

### 3. ขั้นที่ 2: ใส่ข้อมูล 3 แบบ ดู token และคำตอบ

คำถามเดียวกัน `เมล็ดกาแฟดอยช้างราคาเท่าไร` ถามโมเดล 3 ครั้ง ด้วย system ที่ต่างกันที่ส่วนข้อมูล:

| แบบ | ข้อมูลที่ใส่ | สิ่งที่ควรเห็น |
|---|---|---|
| 1 | ไม่ใส่ | ตอบ `ไม่มีข้อมูล` (system บอกให้ตอบจากข้อมูลที่ให้เท่านั้น) token ขาเข้าน้อยสุด |
| 2 | สินค้าทุกชิ้น (`listProducts()`) | ตอบราคาถูก token ขาเข้ามากสุด |
| 3 | เฉพาะที่ค้นเจอ (`searchProducts`) | ตอบราคาถูก token ขาเข้าน้อยกว่าแบบ 2 มาก |

แต่ละแบบพิมพ์ `ขาเข้า: N token` จาก `usage_metadata.input_tokens` ให้เห็นตัวเลขจริง เป็นเรื่องของ **ค่าใช้จ่าย** และ **ความเร็ว** ด้วย (token ขาเข้าเสียโควต้า/เงิน และ prompt ยาวตอบช้าลง) ร้านเรามี 24 ชิ้นยังไม่เห็นปัญหา แต่ร้านจริงมีเป็นพันเป็นหมื่นชิ้น ใส่ทั้งหมดไม่ได้ ช่วงหลังของคอร์สจะให้โมเดลเรียก tool ค้นสินค้า และใช้ RAG (ค้นเอกสารแล้วใส่เฉพาะส่วนที่เกี่ยว) ซึ่งคือหลักการเดียวกับแบบที่ 3 ในบทนี้

### 4. context เต็มแล้วเกิดอะไรขึ้น

โมเดลรับข้อความได้ไม่เกินขนาด **context window** ของมัน ถ้าข้อความที่ส่งยาวเกินไป ระบบบางตัวตัดข้อความส่วนต้นๆ ทิ้ง โดยไม่เตือน ส่วนต้นๆ นั้นมักคือ system prompt กับข้อมูลที่เราใส่ไว้ จึงเกิดอาการ "โมเดลลืมกฎที่ให้ไว้"

ขั้นที่ 1 มีส่วนจำลองที่ให้เห็นภาพ: ข้อความ 26 บรรทัด (system 1 + สินค้า 24 + คำถาม 1) แต่ "เก็บได้แค่ 10 บรรทัดท้าย" ผลคือ system prompt และข้อมูลต้นๆ (P001) หายไป เหลือบรรทัดแรกเป็นสินค้า P016 **ส่วนจำลองนี้เป็นภาพประกอบเท่านั้น ไม่ใช่วิธีตัดของ Ollama จริง** ของจริงนับเป็น token ไม่ใช่เป็นบรรทัด

อาการนี้พบบ่อยกับ Ollama ในเครื่อง เพราะ context ค่าเริ่มต้นของ Ollama ตั้งไว้เล็ก (4k token) ถ้าส่ง prompt ยาวกว่านั้นโดยไม่ได้ขยาย ข้อความต้นๆ จะถูกตัดโดยไม่มีข้อความเตือน ให้ดูค่า `OLLAMA_NUM_CTX` ที่ตั้งไว้ในบท 003

### 5. แบบฝึกหัด: ใส่ข้อมูลให้ละเอียดขึ้น และตัดให้พอดีงบ

- ข้อ 1: เพิ่มสต็อกลงในบรรทัดสินค้า เพื่อให้โมเดลตอบได้ว่า "ยังมีของไหม"
- ข้อ 2: เขียนตัวตัดข้อมูลให้พอดีงบตัวอักษร แล้วดูว่าโมเดลตอบอย่างไรเมื่อสินค้าที่ถามถูกตัดทิ้ง (system บอกให้ตอบ `ไม่มีข้อมูล`)

## จุดที่มักพลาด

- **ไม่ใส่ข้อมูลแล้วคาดว่าโมเดลรู้:** โมเดลรู้เรื่องทั่วไป แต่ไม่รู้ราคาและสต็อกของร้านเรา ถ้าไม่ให้ มันอาจแต่งตัวเลขขึ้นมา
- **ใส่ข้อมูลทั้งหมดทุกครั้ง:** เปลืองเงิน ช้า และเสี่ยงเกิน context window ใส่เฉพาะที่เกี่ยวกับคำถาม
- **พิมพ์ราคาและชื่อสินค้าเองลงใน prompt:** ข้อมูลหลุดจากความจริงเมื่อร้านแก้ราคา ให้สร้างข้อความจากข้อมูลด้วย template string
- **ไม่รู้ว่าข้อความโดนตัด:** ระบบที่ตัดข้อความต้นๆ ไม่เตือน ถ้าโมเดลทำเหมือนไม่เคยได้รับกฎ ให้นึกถึง context เต็มก่อน (บน Ollama ดู `OLLAMA_NUM_CTX`)
- **คิดว่าข้อมูลที่ใส่แล้วถูกต้องเสมอ:** ข้อมูลเก่าที่ใส่ใน prompt ไม่อัปเดตเอง ต้องสร้างใหม่ทุกครั้งที่ถามจากข้อมูลล่าสุด

## ผลที่ควรเห็น

### ขั้นที่ 1: ต้องตรงทุกตัว

ทั้ง `example.ollama` และ `example.google` (ตัวเลขความยาวมาจากผลจริง):

```
--- ขั้นที่ 1: ใส่ข้อมูลสินค้าด้วย template string ---
P001 เมล็ดกาแฟคั่วกลาง ดอยช้าง 250 กรัม ราคา 380 บาท
P002 เมล็ดกาแฟคั่วเข้ม ดอยสะเก็ด 250 กรัม ราคา 360 บาท
P003 เมล็ดกาแฟคั่วอ่อน เอธิโอเปีย 200 กรัม ราคา 520 บาท
... (อีก 21 บรรทัด)
ทุกชิ้น: 24 บรรทัด ยาว 1090 ตัวอักษร
เฉพาะที่ค้นด้วย "ดอยช้าง": 1 บรรทัด ยาว 52 ตัวอักษร
--- จำลอง context เต็ม: เก็บได้แค่ 10 บรรทัดท้าย ---
ข้อความทั้งหมด 26 บรรทัด เหลือ 10 บรรทัด
บรรทัดแรกที่เหลือ: P016 เครื่องชงเฟรนช์เพรส 350 มล. ราคา 650 บาท
system prompt ยังอยู่ไหม: ไม่อยู่
ข้อมูล P001 ยังอยู่ไหม: ไม่อยู่
```

(บรรทัดสินค้ามาจากข้อมูลใน `src/shop` ถ้าผู้สอนแก้ข้อมูลร้าน ตัวเลขเหล่านี้เปลี่ยนตาม)

### ขั้นที่ 2: เทียบกับ checklist

```
--- ขั้นที่ 2: ถามราคาโดยใส่ข้อมูล 3 แบบ ---
--- แบบที่ 1: ไม่ใส่ข้อมูล ---
ขาเข้า: N token
คำตอบ: <คำตอบภาษาไทย>
--- แบบที่ 2: ใส่สินค้าทุกชิ้น ---
ขาเข้า: N token
คำตอบ: <คำตอบที่มีราคา>
--- แบบที่ 3: ใส่เฉพาะสินค้าที่ค้นเจอ ---
ขาเข้า: N token
คำตอบ: <คำตอบที่มีราคา>
```

**`example.ollama` และ `example.google`**
- [ ] ขั้นที่ 1 ตรงกับข้างบนทุกตัว
- [ ] ขั้นที่ 2 ทั้ง 3 แบบมี `ขาเข้า: N token` โดย N มากกว่า 0
- [ ] N ของแบบที่ 2 มากกว่า N ของแบบที่ 3
- [ ] คำตอบของแบบที่ 2 และ 3 มีราคาของ P001 (380 บาท)
- [ ] คำตอบของแบบที่ 1 เป็นภาษาไทย

**`exercise-1.*`**

```
ตรวจตัวอย่าง: <บรรทัดของ P012>
ตรวจตัวอย่าง: <บรรทัดของ P018>
--- คำถามที่ 1 ---
<คำตอบ>
--- คำถามที่ 2 ---
<คำตอบ>
```

- [ ] `ตรวจตัวอย่าง:` บรรทัดแรกมี `P012` ราคาของ P012 (2490 หรือ 2,490) และคำว่า `หมด` และไม่มี `เหลือ N ชิ้น`
- [ ] `ตรวจตัวอย่าง:` บรรทัดที่สองมี `P018` ราคา `450` และ `15` และไม่มีคำว่า `หมด`
- [ ] คำตอบที่ 1 บอกว่าของหมด (มีคำว่า `หมด`, `ไม่มีของ` หรือ `ไม่มีสินค้า`)
- [ ] คำตอบที่ 2 มี `15`

**`exercise-2.*`**

```
ตรวจตัวอย่าง: งบ 4 ตัวอักษร ได้ 1 บรรทัด
ส่งข้อมูล 5 จาก 24 บรรทัด (266 ตัวอักษร)
--- คำถามที่ 1 ---
<คำตอบ>
--- คำถามที่ 2 ---
<คำตอบ>
```

- [ ] มีบรรทัด `ตรวจตัวอย่าง: งบ 4 ตัวอักษร ได้ 1 บรรทัด` ตรงทุกตัว
- [ ] `ส่งข้อมูล N จาก 24 บรรทัด (M ตัวอักษร)` โดย N และ M เท่ากับที่คำนวณจากบรรทัดสินค้าทุกชิ้นกับงบ 300 (ข้างบนคือ 5 และ 266) และ M ไม่เกิน 300
- [ ] คำตอบที่ 1 มีราคาของ P001
- [ ] คำตอบที่ 2 มี `ไม่มีข้อมูล` (สินค้าที่ถามถูกตัดทิ้ง)

> หมายเหตุ: ผลของไฟล์ `.google.ts` ในบทนี้ยังไม่ได้ทดสอบกับ key ของ Google จริง

## แบบฝึกหัด

1. **`exercise-1.*`:** เติม `detailLine(p)` ให้คืนบรรทัดที่มีรหัส ชื่อ ราคา และสต็อกของสินค้า (สต็อก 0 เขียนว่า `หมด` นอกนั้นเขียนว่า `เหลือ N ชิ้น`) ไฟล์ส่งสินค้าทุกชิ้นด้วย `detailLine` แล้วถาม `เครื่องบดกาแฟไฟฟ้ายังมีของไหม` และ `แก้วมัคสแตนเลสเก็บความเย็นเหลือกี่ใบ`
2. **`exercise-2.*`:** เติม `fitBudget(lines, maxChars)` ให้เก็บบรรทัดจากต้นไปเรื่อยๆ ตราบที่ข้อความรวม (ต่อบรรทัดด้วย `\n`) ยาวไม่เกิน `maxChars` ตัวอักษร ไฟล์ใช้งบ 300 ตัวอักษรกับบรรทัดสินค้าทุกชิ้น แล้วถาม `เมล็ดกาแฟดอยช้างราคาเท่าไร` และ `ผ้ากันเปื้อนบาริสต้าราคาเท่าไร`

ไฟล์แบบฝึกมี 👉 และค่าชั่วคราวไว้ให้รันได้ แต่ผลจะยังไม่ผ่าน checklist จนกว่าจะแก้ครบ ถ้าติด เปิดไฟล์ `example.*` ข้างๆ และอ่านเฉลยบน branch `solutions` เมื่อทำเองแล้ว

# บท 010: ค่าตั้งของโมเดล temperature และการจำกัดความยาว

บท 007-009 เราสร้างโมเดลด้วยค่าเริ่มต้นแล้วถามเลย บทนี้เรียนว่าตอนสร้างโมเดลตั้งค่าอะไรเพิ่มได้บ้าง และค่าไหนทำให้คำตอบ **นิ่งขึ้น** หรือ **สั้นลง** ใช้เวลาประมาณ 45-60 นาที ทำทั้งแบบ Ollama (`.ollama.ts`) และ Google (`.google.ts`)

## จบบทนี้แล้วทำอะไรได้

- อธิบายได้ว่า `temperature` ทำอะไรกับคำตอบ และทำไมตั้ง 0 แล้วก็ยังอาจได้คำตอบไม่เหมือนกัน
- ตั้ง `temperature` และ `numPredict` ให้ `ChatOllama` ตั้ง `maxOutputTokens` ให้ `ChatGoogle`
- รู้ว่า Gemini รุ่นใหม่ไม่ใช้ `temperature` และใช้ system prompt ที่ชัดเจนคุมคำตอบแทน
- ตรวจได้ว่าคำตอบถูกตัดกลางคันเพราะเกินโควต้า token หรือไม่ โดยอ่านเหตุที่โมเดลหยุด

## เนื้อหา

บทนี้ต้องผ่านบท 009 ก่อน

### 1. temperature คืออะไร

ทุกครั้งที่โมเดลเลือกคำถัดไป มันให้คะแนนกับคำที่เป็นไปได้ทั้งหมด แล้วแปลงคะแนนเป็นโอกาส (รวมกันได้ 100%) ด้วยสูตรที่เรียกว่า softmax โดย **หารคะแนนด้วย temperature ก่อน**:

- `temperature` น้อย (เช่น 0.2): ผลต่างของคะแนนถูกขยาย คำที่คะแนนสูงสุดได้โอกาสเกือบทั้งหมด คำตอบนิ่ง
- `temperature` มาก (เช่น 2): ผลต่างของคะแนนถูกบีบ ทุกคำได้โอกาสใกล้กัน คำตอบหลากหลายและเสี่ยงหลุดประเด็น
- `temperature` เท่ากับ 0: ในทางปฏิบัติคือเลือกคำที่คะแนนสูงสุดเสมอ (ไลบรารีไม่ได้หารด้วย 0 จริง)

ขั้นที่ 1 ของไฟล์ตัวอย่างลองคำนวณให้ดู ด้วยคะแนนสมมติของ 3 คำ `{ กาแฟ: 2, ชา: 1, โกโก้: 0.5 }` ไม่ยิงเน็ตและผลเหมือนกันทุกครั้ง

### 2. ตั้งค่าใน ChatOllama

```ts
const model = new ChatOllama({
  model: env("OLLAMA_MODEL"),
  baseUrl: env("OLLAMA_BASE_URL"),
  temperature: 0,
});
```

| ค่าตั้ง | ความหมาย |
|---|---|
| `temperature` | ตามหัวข้อที่แล้ว ใส่ 0 เมื่ออยากได้คำตอบนิ่งที่สุด |
| `numPredict` | จำนวน token สูงสุดที่โมเดลจะสร้างในคำตอบหนึ่งครั้ง |

ไฟล์ตัวอย่างฝั่ง Ollama ถามคำถามเดิม `ตั้งชื่อร้านกาแฟเล็กๆ ในซอย 1 ชื่อ ตอบแค่ชื่อ` ชุดละ 3 ครั้งต่อกัน ชุดที่ 1 ใช้ `temperature 0` ชุดที่ 2 ใช้ `temperature 1.5` แล้วนับว่าได้กี่แบบ

### 3. Gemini: ไม่ส่ง temperature

Gemini รุ่นใหม่แนะนำให้ใช้ค่าเริ่มต้นของ `temperature` (รุ่นถัดๆ ไปอาจปฏิเสธค่าที่ส่งเข้าไป) ดังนั้นฝั่ง Google ในคอร์สนี้ **ไม่ส่ง `temperature`** และใช้ system prompt ที่ชัดเจนทำให้คำตอบนิ่งแทน ไฟล์ตัวอย่างฝั่ง Google ถามคำถามเดิมชุดละ 3 ครั้ง ชุดที่ 1 ไม่มี system prompt ชุดที่ 2 มี system prompt `ตอบเป็นชื่อร้าน 1 ชื่อ ภาษาไทย ไม่เกิน 3 คำ ไม่มีคำอธิบาย` แล้วเทียบว่าชุดไหนได้คำตอบน้อยแบบกว่า

### 4. จำกัดความยาวและอ่านเหตุที่หยุด

ตั้งเพดานจำนวน token ของคำตอบได้ ถ้าโมเดลสร้างถึงเพดานก่อนจบ คำตอบจะถูก **ตัดกลางคัน** ทันที:

| provider | ค่าตั้ง | ค่า "เหตุที่หยุด" เมื่อถูกตัด | อ่านจาก |
|---|---|---|---|
| Ollama | `numPredict: 20` | `length` | `res.response_metadata.done_reason` |
| Google | `maxOutputTokens: 20` | `MAX_TOKENS` | `res.response_metadata.finish_reason` หรือ `finishReason` (ตามบท 008) |

เมื่อโมเดลจบเองตามปกติ ค่าจะเป็น `stop` (ฝั่ง Gemini อาจเป็นตัวพิมพ์ใหญ่) ใช้ค่านี้เช็กว่าคำตอบที่ได้ครบหรือโดนตัด ซึ่งสำคัญเมื่อต้องเอาคำตอบไปทำงานต่อ เช่น แปลงเป็น JSON ที่ถูกตัดกลางคันจะใช้ไม่ได้

## จุดที่มักพลาด

- **คิดว่า `temperature: 0` ให้คำตอบเหมือนเดิมเป๊ะทุกครั้ง:** ไม่รับประกัน การคำนวณบนเครื่อง ตัวโมเดล และการรันบนเซิร์ฟเวอร์ที่ต่างกันทำให้คำตอบต่างกันได้ ลองรันไฟล์ตัวอย่างหลายรอบและสังเกตว่าบางทีชุดที่ 1 ก็ยังไม่ได้ 1 แบบ
- **ส่ง `temperature` ให้ Gemini:** รุ่นใหม่ไม่สนค่านี้ และรุ่นถัดไปอาจ error (400) ใช้ system prompt คุมแทน
- **ตั้ง `numPredict` หรือ `maxOutputTokens` น้อยเกินไป:** คำตอบถูกตัดกลางประโยค ถ้าต้องการคำตอบสั้น ให้บอกใน system prompt ว่าสั้นแค่ไหน และใช้เพดานเป็นแค่ตัวกันเกินเท่านั้น
- **โมเดลที่คิดก่อนตอบ (บท 011) อาจได้ข้อความว่างทั้งที่ `จบเพราะ: length`:** โมเดลพวกนี้ใช้ token ไปกับ "ความคิด" ก่อนเริ่มตอบ ถ้าเพดานน้อยมาก (เช่น 20) token หมดตั้งแต่ยังคิดไม่จบ จึงไม่มีข้อความคำตอบเหลือเลย (ผลทดลองกับโมเดลที่ใช้ทดสอบของคอร์สเจอแบบนี้ ไฟล์ตัวอย่างจึงยอมรับ `ได้ข้อความ: 0 ตัวอักษร`) ดูต่อในบท 011
- **เรียกคำถามซ้ำพร้อมกัน (ขนาน) เพื่อให้เร็ว:** บทนี้ถามทีละครั้งเพราะเจอข้อจำกัดโควต้าได้ง่าย (429) เรื่องการเรียกพร้อมกันอยู่ในบทหลังๆ
- **ลืมเปิด Ollama / เจอ 429 / ชื่อโมเดลผิด:** เหมือนบท 006 และ 007 (บท 012 จะเรียนวิธีอ่าน error เหล่านี้)

## ผลที่ควรเห็น

### ขั้นที่ 1: ต้องตรงทุกตัว

ทั้ง `example.ollama` และ `example.google`:

```
--- ขั้นที่ 1: temperature เปลี่ยนโอกาสของคำถัดไป ---
t=0.2: กาแฟ 99% | ชา 1% | โกโก้ 0%
t=1: กาแฟ 63% | ชา 23% | โกโก้ 14%
t=2: กาแฟ 48% | ชา 29% | โกโก้ 23%
```

### ขั้นที่ 2: เทียบกับ checklist

ต่อจากขั้นที่ 1 จะเป็น `--- ขั้นที่ 2: ถามซ้ำ 3 ครั้ง ---` ตามด้วย 2 ชุด และส่วนจำกัดความยาว ซึ่ง **เปลี่ยนไปทุกครั้ง** รูปร่างที่ควรเห็น (ฝั่ง Ollama):

```
--- ขั้นที่ 2: ถามซ้ำ 3 ครั้ง ---
ชุดที่ 1 (temperature 0): <ชื่อ> | <ชื่อ> | <ชื่อ>
ต่างกัน: N แบบ จาก 3 ครั้ง
ชุดที่ 2 (temperature 1.5): <ชื่อ> | <ชื่อ> | <ชื่อ>
ต่างกัน: N แบบ จาก 3 ครั้ง
--- จำกัดความยาว (numPredict 20) ---
จบเพราะ: length
ได้ข้อความ: N ตัวอักษร
```

ฝั่ง Google หัวข้อของชุดเป็น `ชุดที่ 1 (ไม่มี system prompt)` กับ `ชุดที่ 2 (มี system prompt คุมรูปแบบ)` และส่วนจำกัดความยาวเป็น `--- จำกัดความยาว (maxOutputTokens 20) ---` กับ `จบเพราะ: MAX_TOKENS`

**`example.*`**
- [ ] ขั้นที่ 1 ตรงกับด้านบนทุกตัวอักษร (3 บรรทัด `t=...`)
- [ ] มีบรรทัด `ชุดที่ 1 (` และ `ชุดที่ 2 (` และแต่ละบรรทัดมี 3 คำตอบที่ไม่ว่าง คั่นด้วย ` | `
- [ ] บรรทัด `ต่างกัน: N แบบ จาก 3 ครั้ง` มี 2 บรรทัด N เป็น 1-3 และเท่ากับจำนวนคำตอบที่ไม่ซ้ำกันในบรรทัดชุดนั้น
- [ ] ส่วนจำกัดความยาวมี `จบเพราะ: length` (Ollama) หรือ `จบเพราะ: MAX_TOKENS` (Google)
- [ ] มีบรรทัด `ได้ข้อความ: N ตัวอักษร` (N เป็น 0 ได้ ตามที่อธิบายใน "จุดที่มักพลาด")

**`exercise-1.*`**
- [ ] มีบรรทัด `จำกัด 20: ถูกตัด` และบรรทัด `ไม่จำกัด: ครบ`

**`exercise-2.*`**
- [ ] มี `ครั้งที่ 1:` ถึง `ครั้งที่ 3:` และทุกบรรทัดมีคำตอบรูปแบบ `เวลาเปิด: HH:MM-HH:MM` (เช่น `เวลาเปิด: 09:00-20:00` เครื่องหมาย `**` ไม่นับ)

> โมเดลอาจใส่เครื่องหมาย `**` (Markdown ตัวหนา) มาในคำตอบ ไม่ใช่บั๊ก

## แบบฝึกหัด

1. **`exercise-1.*`:** เติม `isCutOff(msg)` ให้คืน `true` เมื่อ `AIMessage` ถูกตัดเพราะถึงขีดจำกัดความยาว ไม่เช่นนั้น `false` แล้วไฟล์จะถาม 2 ครั้ง (คำถามยาวที่จำกัด 20 token กับคำถามสั้นที่ไม่จำกัด) และพิมพ์ `จำกัด 20: ถูกตัด` กับ `ไม่จำกัด: ครบ`
2. **`exercise-2.*`:** เติม `systemPrompt()` ให้คืน system prompt ที่บอกว่าร้านเปิด 09:00-20:00 และบังคับให้ตอบรูปแบบ `เวลาเปิด: HH:MM-HH:MM` แล้วไฟล์จะถาม `ร้านเปิดกี่โมงครับ` 3 ครั้ง (ฝั่ง Ollama ตั้ง `temperature: 0` ไว้ให้แล้ว) ทุกครั้งต้องได้รูปแบบเดียวกัน
